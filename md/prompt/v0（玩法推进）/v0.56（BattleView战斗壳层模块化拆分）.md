# v0.56 / BattleView 战斗壳层模块化拆分

## 版本号与分配依据

- 版本号：`v0.56`。
- 分配依据：当前最新正式版本与提示词为 `v0.55`，本轮顺延一个小版本。
- 本轮承接 `md/unity分析/Unity迁移分析报告.md` 的结论：不为解决 SwiftUI 文件膨胀全量迁移 Unity，先拆分 `BattleView`；同时遵守人工要求，由 Agent X 顺序执行 A/B/C 职责，不启用子 Agent。

## 背景

`BattleView.swift` 当前约 8,763 行，集中包含战斗根壳层、顶部资源带、边缘抽屉、选择命令坞、地图渲染、地形材质、战斗读板、按钮样式和领域展示扩展。v0.52-v0.55 已把视觉方向推进到地图主导、薄顶部、横向边缘工具和目标导向命令坞，但继续在单文件内叠加地图、AI 和将领 UI 会放大编译清单遗漏、私有访问边界和视觉回归风险。

Agent X 已重新核对 Google Play 官方公开截图。只提炼“地图占主体、顶部资源带紧凑、边缘高频控制、地图上直接表达城市/军团、详情通过覆盖层出现”的布局规律；不得复制、下载进仓库或描摹原游戏图片、人物、图标、品牌和文本。

## 本轮目标

1. 将 `BattleView.swift` 按稳定 UI 子域拆成根壳层、壳层控制、战场地图、战斗面板和共享样式五个编译单元。
2. 保持全部现有类型名、初始化参数、环境对象、状态所有权、action、disabled 条件、无障碍语义、视觉常量和绘制顺序不变。
3. 让 Xcode target、RenderBattlePreview 独立编译命令和结构检查都显式覆盖新文件，避免“App 能编译但预览缺文件”或相反。
4. 将文档更新为真实模块边界，并把 workflow artifact 版本提升为 v0.56。
5. 为下一轮拆分 `GameViewModel` 和继续优化地图、AI、将领界面建立更小的修改面。

## 非目标

- 不改 `GameState`、`GameViewModel`、AI 评分或执行、移动、攻击、技能、姿态、任务、经济、存档、外交和回合规则。
- 不调整颜色、字体、间距、地图尺度、overlay 权重、按钮层级、抽屉行为或屏幕文案。
- 不新增第三方框架，不迁移 Unity，不引入新资源资产。
- 不趁拆分进行命名清理、现代 API 全量替换或每类型一文件的大爆炸式重构。
- 不创建分支、PR 或候选分支，不运行任何本地验证命令。

## 当前架构依据

- `BattleView.swift` 的根视图只持有 `activeDrawer` 本地 UI 状态，并通过 `GameViewModel` 展示与触发命令。
- `BattleInterfaceMetrics`、`MapOverlayPresentation`、`HexMetrics` 与现有 RenderBattlePreview 断言共享稳定布局和显示策略。
- `Tools/verify_project.mjs` 当前只读取单个 `BattleView.swift` 搜索结构 token，拆分后必须改为聚合全部战斗视图源码。
- `.github/workflows/ci-results.yml` 与 README/test 中的 SwiftUI/Render 命令当前只列出 `BattleView.swift`，拆分后必须同步显式列出新文件。
- Xcode 工程仍使用显式 PBX file reference/source build phase；新增源码必须进入 Views group 和 Sources phase。

## 实现步骤

1. 保留 `BattleView.swift` 中 `BattleInterfaceMetrics` 与 `BattleView` 根壳层，使入口文件直接表达布局所有权和抽屉本地状态。
2. 新建 `BattleShellControls.swift`，移动 `BattleDrawerCategory`、`MapOverlayPresentation`、顶部栏、边缘工具、抽屉、选择命令坞及其命令按钮。
3. 新建 `BattleMapView.swift`，移动 `WarMapView`、地图 HUD、背景、六边格、路线/目标 overlay、地貌纹理、城市和军团 token。
4. 新建 `BattlePanels.swift`，移动完整/紧凑命令面板、战场/敌情/城市/将领/任务/科技/外交/战报读板及地图图例/目标阶段 UI。
5. 新建 `BattleViewStyles.swift`，移动命令按钮标签与样式、`HexMetrics`、基础 shape 以及阵营/地形/单位/报告展示扩展。
6. 只做机械移动；除每个新文件增加 `import SwiftUI` 外，不改动移动代码内容。检查跨文件访问级别，保持原有 `private` 成员只在其所属类型或同一子域使用。
7. 更新 `project.pbxproj`、workflow Render 编译清单、`Tools/verify_project.mjs`、README 和测试文档中的源码清单；结构检查应聚合五个战斗视图文件再验证既有 token。
8. 更新 `README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`md/prompt/README.md` 与 `update_log.md`，workflow artifact 版本改为 v0.56。
