# v0.63 战斗目标锁定身份与取消入口

## 版本号与分配依据

- 版本号：v0.63。
- 依据：v0.62「战斗目标锁定与攻击预演」已由云端验收通过；本轮继续沿用既有锁定态和 `SelectedCombatForecast`，补齐目标身份链、紧凑/完整预演一致性以及显式取消入口，不重复实现 v0.62 已完成的基础锁定流程。

## 背景

v0.62 已把地图徽标、目标菜单和抽屉攻击列表改为“先锁定、再预演、最后确认”，并让 `SelectedCombatForecast` 复用核心 `GameState.attackPreview`。当前仍有三个交互缺口：锁定后在不同层级读板中不一定持续显示攻击者和防守者身份，紧凑命令坞与完整抽屉可能只显示不同粒度的数字摘要，且没有明确的取消锁定动作。玩家需要能够确认“谁正在攻击谁”、在不同屏幕密度下看到同一份结果，并能回到选中军团而不改变战局。

本轮目标是把攻击目标锁定做成一条可追踪、可取消、不可误结算的 UI 状态链。所有规则仍由核心层提供，锁定和取消只属于 `GameViewModel` 的选择态。

## 本轮目标

1. 保持锁定目标的身份链完整可见：在地图聚焦态、底部命令坞、紧凑命令面板、完整抽屉/行动面板以及 VoiceOver 标签中，始终明确显示攻击者（己方军团/将领/位置）和防守者（敌方军团/将领/位置）；不能只显示“目标 1”或伤害数字。
2. 让紧凑和完整攻击路径共用同一 `SelectedCombatForecast` 字段、同一攻击者/防守者名称和同一结果/修正文案。可以改变布局和信息密度，但不能重新计算或出现互相矛盾的伤害、反击、剩余生命、修正、结果标签。
3. 在 `GameViewModel` 增加 ViewModel-only 的显式取消命令（建议命名 `cancelSelectedAttackTarget()`，若现有命名风格有更好等价名称可说明理由）：清除 `selectedAttackTargetID` 以及仅与锁定相关的焦点/横幅状态，不修改 `GameState`、单位、城市、资源、回合、活动阵营、AI 意图或存档；尽量保留选中的己方攻击者和其上下文。
4. 从命令坞/预演读板提供可发现的取消入口，并让地图、紧凑菜单、完整抽屉在锁定状态下都能通过清晰的按钮链路取消；取消后可重新打开合法目标列表，不得自动调用 `attack(_:)`。
5. 在完整目标行、紧凑目标菜单和地图叠层上提供明确的选中/锁定视觉状态（焦点环、标签或图标等组合），不能只依赖颜色；保持现有攻击起点高亮、镜头聚焦和地图空间层逻辑。

## 非目标

- 不修改 `Sources/RomeLegionsCore/GameState.swift` 的攻击公式、伤害、反击、支援/包夹/指挥/守援修正、战斗结果或 Codable 存档结构。
- 不新增跨回合命令队列、目标预留、批量攻击计划、自动确认、预输入或网络同步。
- 不改变 AI 评分、AI 意图预测、敌军行动、城市规则、将领技能规则、外交、地图镜头数学或 `MapViewportState` 的职责。
- 不把锁定态写入 `GameState`、`SaveStore`、AI 输入或任何持久化结构；不通过通知、全局单例或额外状态源绕开 `GameViewModel`。
- 不进行 Unity 迁移、不引入第三方框架、不进行全局 Observation/导航重构，也不重做 v0.62 已验收的攻击确认流程。
- 不把复杂规则或预演计算写入 SwiftUI `body`、按钮闭包、`onTapGesture` 或生命周期回调。

## 当前架构依据

- `GameState.attackPreview(attackerID:defenderID:)` 是攻击预演唯一来源；`GameState.attack(attackerID:defenderID:)` 继续使用同源规则，确认入口只能通过现有 `confirmSelectedAttack` 调用结算。
- `GameViewModel` 持有 `selectedAttackTargetID`、选择态和命令态；`GameViewModelSelectionReadouts.swift` 承载 `SelectedCombatForecast` 及 UI 友好的派生字段。锁定/取消不得改变核心 `gameState`。
- `BattleMapView.swift` 承载地图空间层、攻击者起点与防守者目标入口；`BattleShellControls.swift` 承载底部命令坞和紧凑命令路径；`BattlePanels.swift` 承载完整抽屉、行动面板、目标行和预演读板；共享文案/样式应继续放在已有 View/Style 边界内。
- `MapViewportState` 只管理缩放、拖移、选择聚焦和复位；若取消需要镜头处理，应使用现有选择/聚焦命令并避免把取消态写入玩法状态。
- v0.62 已保留地图攻击起点高亮、目标锁定、`CombatForecastReadoutView` 和目标可访问性处理；本轮应扩展这些链路而不是复制一套攻击状态。

## 实现步骤

### 1. 梳理锁定状态和身份派生

- 阅读当前 `focusAttackTarget(_:)`、`selectedAttackTargetID`、`selectedCombatForecast`、`confirmSelectedAttack` 以及攻击入口的所有调用方，列出地图、命令坞、紧凑面板、完整抽屉的状态流。
- 在 `SelectedCombatForecast` 或同层 UI 派生结构中提供稳定的攻击者/防守者身份字段：军团名称/阵营、将领（若有）、六边形位置，以及现有伤害、反击、双方剩余生命、修正和预计结果字段。优先复用已有模型和格式化 helper，避免各视图自行拼接身份或重复查找单位。
- 确认目标失效、回合切换、确认结算和取消时的清理行为；任何清理都必须保持现有合法性检查和错误消息语义，不得让旧锁定继续显示为可确认。

### 2. 建立显式取消命令

- 在 `GameViewModel` 增加 `cancelSelectedAttackTarget()`（或等价的明确命名），仅清除攻击目标选择及锁定专属的焦点/横幅状态。
- 取消时保留己方选中攻击者（如果其仍然存在且合法），尽量让地图/命令坞仍展示该军团的处境和可用攻击入口；不要把选择无条件切到敌方目标或重置整个回合。
- 取消命令必须是幂等的：无锁定时调用不会改变 `GameState` 或产生错误；有锁定时只改变 ViewModel 选择态。确认结算仍是唯一允许进入 `attack(_:)` 的路径。
- 若当前 `focusAttackTarget` 会把 `selectedPosition` 切到防守者位置，设计取消后的选择/镜头恢复策略并用注释或派生状态说明；不能为了取消而直接改核心选择源或持久化状态。

### 3. 对齐所有 UI 入口和身份链

- 地图：保留攻击起点和目标焦点环；锁定徽标/目标叠层显示攻击者 -> 防守者身份或可读的等价标签。新增取消按钮必须使用 SwiftUI `Button`、至少 44pt 命中区、VoiceOver label/hint 和非颜色选中信号。
- 底部命令坞/紧凑命令面板：有锁定时同时显示攻击者与防守者、位置、预演结果，并提供“取消锁定”命令；确认按钮仍是唯一结算入口。无锁定时仍列出全部合法目标，不回退到 `.first`。
- 完整抽屉/行动面板：所有目标行显示完整身份和锁定态；当前行要有稳定的视觉选中/锁定样式和明确的取消入口。未选中的合法目标继续调用 `focusAttackTarget`，不能在行内直接结算。
- `CombatForecastReadoutView` 或现有共用读板应成为紧凑/完整路径的同源展示组件；如果需要新增布局参数，只改变排版，不改变字段来源。结果/修正文案必须来自 `SelectedCombatForecast`。
- VoiceOver：锁定行、预演读板、地图焦点和取消按钮要能读出“攻击者 -> 防守者”、位置、伤害/反击/结果及操作提示；不要因重复地图元素产生重复入口，遵守 v0.62 的目标辅助功能隐藏策略。
- Dynamic Type 和窄屏：长军团名、将领名、位置、取消文案可换行或压缩层级，不得遮挡确认/取消按钮、地图固定 HUD 或命令坞；不使用新 `onTapGesture` 代替按钮。

### 4. 完善云端预览 fixture 和结构门禁

- 在 `Tools/RenderBattlePreview/main.swift` 复用 v0.62 的相邻敌军 fixture：锁定目标后断言身份字段在紧凑/完整派生读板中一致，`SelectedCombatForecast.preview == state.attackPreview`，并断言锁定仅改变 ViewModel 选择态。
- 调用取消命令，断言 `selectedAttackTargetID == nil`，攻击者选择仍按约定保留（若因失效而清理需明确断言），且单位、城市、资源、回合、活动阵营、AI/存档快照均不变；取消后再确认不存在可误触的旧目标状态。
- 在单位场景覆盖地图/命令坞/完整抽屉的锁定身份和取消入口；取消后清理锁定，再继续既有城市场景和所有 v0.62 读板断言。
- 更新 `Tools/verify_project.mjs`、`.github/workflows/ci-results.yml` 和相关断言/版本 token，确保结构检查能识别取消命令、身份派生、紧凑/完整共用预演读板和不可绕过确认的入口。

## 验收标准

- 地图、紧凑命令坞、紧凑预演、完整抽屉和 VoiceOver 在锁定状态都能明确表达同一条攻击者 -> 防守者身份链（名称/阵营、将领如有、位置），没有只剩数字或“目标 1”的降级文案。
- 紧凑与完整路径读取同一个 `SelectedCombatForecast`；伤害、反击、双方剩余生命、支援/包夹/指挥/守援修正和预计结果完全一致，且预演仍与 `GameState.attackPreview` 同源。
- “取消锁定”是可发现、可访问的 SwiftUI 按钮，调用只清理 ViewModel 锁定态并尽量保留攻击者选择；重复取消安全，取消前后核心状态快照完全不变。
- 只有确认命令能调用 `attack(_:)`；任意地图徽标、菜单或抽屉目标行都不能直接结算，也不能隐式取 `.first`。
- 目标行和地图焦点具有不依赖颜色的选中/锁定信号，所有新控件命中区至少 44pt，支持 Dynamic Type、窄屏换行和 VoiceOver，不遮挡固定 HUD、地图或命令坞。
- 最新云端 CI 的结构检查、Swift Testing、Gameplay Smoke、RenderBattlePreview 六图和无签名 Xcode build 均通过；Agent C 已核对最新 manifest/JUnit/log/PNG，且没有使用旧 run、旧 artifact 或本地输出冒充结果。
- 相关 README、flow、flowchart、test、prompt 索引、CI/结构门禁和（验收后）`update_log.md` 与真实实现同步。
