## 背景

当前 AI 将领已经能在原地发动主动技能，`AIIntent.kind == .useSkill`、`GeneralSkillPreview`、AI 作战计划和敌将威胁报告也能表达原地施令。但真实 `performSimpleAI(for:)` 的移动分支只会“移动后攻击”，不会为了新的合法技能覆盖面先机动再施令。

这造成四个同源缺口：

1. 原地没有收益、合法移动后才可恢复友军或削弱敌城时，AI 意图仍不会产生移动施令。
2. 真实执行不会走“合法移动 -> 重新确认技能 -> 发动技能”。
3. `AIPlanStepReport` 的技能摘要仍来自原位置 `LegionFormationReport`，不是意图落点后的预览。
4. `EnemyCommanderThreatReport` 在原位置重新生成技能预览；因此其 `destination` 可能指向移动落点，但 `rangePositions`、`affectedPositions`、目标和预计收益仍属于原位置，地图也会据此画出错误技能范围。

已有 `GeneralSkillPreview` 已完整承载起点、范围、受影响对象、预计恢复/削城防、冷却、可执行性、阻塞原因和文案；`AIIntent` 现有 `destination`、`targetUnitID`、`targetCityID`、`threatScore` 足以表达移动施令。本轮必须复用这些既有字段，不增加 Codable 或存档状态。

## 本轮唯一主目标

让 AI 将领能够移动到合法落点后发动主动技能，并让下列链路共用该落点后的同一 `GeneralSkillPreview` 语义：

```text
合法落点候选
  -> 落点 GeneralSkillPreview
  -> AIIntent(.useSkill, destination, target IDs, threatScore)
  -> AI 作战计划 step/summary/detail
  -> EnemyCommanderThreatReport
  -> EnemyCommanderThreatSummary / MapOverlay 技能范围与影响区
  -> performSimpleAI 真实移动后重新预览并 useGeneralSkill
```

必须同时保护：存在当前可直接歼灭的目标时，有收益的“移动后施令”不得抢走该立即击杀；这一优先级必须由候选层/词典序硬保证，不能依赖继续增大某个 magic number。

## 当前架构依据

### 核心类型和预测入口

- `Sources/RomeLegionsCore/GameState.swift`
  - `GeneralSkillPreview`：现有唯一技能效果预览值，字段已足够，不增字段。
  - `AIIntent` / `.useSkill`：现有 destination、目标和威胁字段足够表达移动施令，不增字段。
  - `generalSkillPreview(unitID:)` / `generalSkillPreview(for:)`：唯一技能范围、目标、收益和可执行性计算器。
  - `aiPlanningForecast(for:)`：把目标敌方刷新到只读规划态，调用前后原 `GameState` 必须相等。
  - `aiPlanningUnit(from:order:position:hasMoved:hasActed:)`：可合成移动落点单位。
  - `reachablePositions(for:)`：真实合法移动候选来源；不得自行计算伪落点。
  - `shouldAIUseGeneralSkill`、`aiSkillTargetUnit`、`aiSkillTargetCity`、`aiSkillThreatScore`：现有技能收益阈值、目标与威胁评分依据。

### 意图与真实执行

- `aiIntent(for:)` 当前只在移动前生成 `.useSkill`；移动落点只生成 `.advanceAttack`、夺城、推进或固守。
- `bestAITarget` 已先筛立即击杀候选，再在同层使用战术分；v0.61 的击杀候选硬层不得退化。
- `bestAIDestination` / `aiPositionScore` 当前只评价攻击、距离、城市和地形，不评价移动后技能。
- `performSimpleAI(for:)` 当前顺序为休整、原地技能、直接攻击、移动、移动后攻击；移动施令必须接入真实主循环并在真实移动后重新预览。
- `moveUnit(id:to:)` 会执行合法性、位置更新、可能占城和战役进度；预测落点必须考虑真实移动后城市归属语义，不能让占领前的敌城被错误计入落点技能预览。
- `useGeneralSkill(unitID:)` 会从当前真实位置重新生成 preview、应用恢复/削城防、设置 `hasMoved/hasActed` 和冷却；真实执行不得绕过该入口直接改单位或城市。

### 计划、敌将报告和地图

- `aiOperationalPlanReports` -> `aiPlanStepReport` 当前 `.useSkill` 的 `skillSummary`/detail 来自原位 formation，需要改为 intent destination 对应的 preview。
- `enemyCommanderThreatReports` 已在敌方 planning forecast 上组装 intent，但私有 `enemyCommanderThreatReport` 当前又从原位置重建 preview；必须改为 intent destination 对应的 preview。
- `EnemyCommanderThreatReport` 已包含 `position`、`destination`、目标、预计恢复/削城防、`rangePositions` 和 `affectedPositions`；不增字段。`position` 继续表示敌将真实起点，`destination` 表示意图落点，技能范围/影响来自 destination preview。
- `GameViewModel` 和 `EnemyCommanderThreatMapOverlay` 继续只消费 report，不在 SwiftUI 或 ViewModel 中重算技能范围。

## 实现设计与步骤

### 1. 建立私有、非持久的移动施令候选

在 `GameState.swift` 增加私有纯值候选，例如：

```swift
private struct AIGeneralSkillCandidate {
    var unitID: String
    var destination: Position
    var preview: GeneralSkillPreview
    var targetUnitID: String?
    var targetCityID: String?
    var score: Int
}
```

名称可等价，但必须满足：

- 不是 public/Codable，不进入 `GameState` stored property、存档或跨回合缓存。
- `preview` 是候选唯一效果来源；不要另存一套范围、恢复或削城防数值。
- 该候选只负责新的“移动后施令”分支，位置来自 `reachablePositions(for:)`；原地施令继续走现有 `shouldAIUseGeneralSkill` 分支，不与新候选重新评分，避免改变旧优先级。

新增 `bestAIGeneralSkillCandidate` 或等价 helper：

1. 输入当前 planning unit，并按需要输入允许的位置集合。
2. 候选位置只来自 `reachablePositions(for:)`；已移动单位不得再次产生移动施令候选。
3. 对每个移动落点，用 `aiPlanningUnit` 合成 `position=destination`、`hasMoved=true`、`hasActed=false` 的单位。
4. 在临时 forecast 副本中替换该单位，并通过唯一 capture-aware projected-state helper 精确模拟 `moveUnit` 会造成的占城、城防归属和 `evaluateCampaignProgress` 结果后，再调用唯一 `generalSkillPreview(for:)`；若落点移动会直接结束战役，候选无效。不得在原 state 写入位置、城市或 campaign status。
5. 继续复用当前 trait 的收益门槛：攻城技能必须有可削弱敌城；恢复技能必须有符合现有阈值的受益单位。只“范围更大”但没有有效收益的落点不是技能候选。
6. `targetUnitID`、`targetCityID` 和 score 从该候选 preview 派生，不得再次按原位置选目标。
7. 稳定排序至少包含 score、是否原地/移动、目标 ID、移动距离、destination y/x、unitID 或语义等价的确定性 tie-break；禁止依赖 `Set`/数组偶然顺序。

### 2. 保留旧行动顺序，并以分支边界保护立即击杀

- `aiIntent(for:)` 与 `performSimpleAI(for:)` 都必须保留既有前半段顺序：休整 -> 有收益的原地技能 -> 当前合法直接攻击。原地技能继续保持旧的技能优先语义；任何当前直接攻击（包括非致死攻击）继续发生在移动分支之前。
- 只有原地技能和直接攻击都不存在时，才进入新的移动决策，并在移动后技能、移动后攻击、夺城/推进候选之间做明确、可审计的比较。
- 因此当前可立即击杀目标天然位于移动后施令之前，是控制流/候选层硬边界；不得为了移动技能把它们放入同一个纯数字 score 池，也不得用 `skillScore - 100`、`killBonus + 500` 等 magic number 宣称硬优先。
- 移动决策内部可使用枚举 action priority + 现有战术/技能 score + 稳定 tie-break，但意图与真实执行必须使用同一语义，不能一个选技能、另一个选移动后攻击。
- 必须增加冲突回归测试：一组证明原地有收益技能时仍沿用旧原地施令行为；另一组证明直接立即击杀存在时移动后施令候选无法进入选择。

### 3. 让 AIIntent 表达移动后施令

- `aiIntent(for:)` 对选中的移动技能候选返回 `.useSkill`。
- `unitID`/`faction`/`tacticalOrder` 保持现有来源。
- `destination` 必须等于候选 preview.origin；移动施令时不得仍写原位置。
- `targetUnitID`/`targetCityID` 必须来自候选 preview 的现有目标选择 helper。
- `projectedDamage` 继续为 nil；`threatScore` 使用候选同一 preview 的 `aiSkillThreatScore` 或等价同源评分。
- 不给 `AIIntent` 增加 preview、range 或 projectedRecovery 字段；需要完整效果的下游使用 `intent.destination` 在同一 planning forecast 中重建同源 preview。
- `aiIntents(for:)` 的所有读取保持只读；调用前后单位、城市、资源、回合、active faction、campaign status、存档编码完全相等。

### 4. 真实执行移动后重新预览并施令

`performSimpleAI(for:)` 选中移动施令候选后：

1. 仍只通过 `moveUnit(id:to:)` 移动，不直接写 `units[index].position`。
2. 移动成功后立即检查 `campaignStatus`；若占城已结束战役，不继续施令。
3. 从当前真实 state 重新读取 commander，并调用当前真实位置的 `generalSkillPreview`/收益判断；不得盲信移动前保存的 preview。
4. 确认真正 preview 仍 executable 且符合原 trait 收益阈值后，调用 `useGeneralSkill(unitID:)`。
5. 真实 `useGeneralSkill` 的受影响单位/城市、恢复/削城防、冷却、`hasMoved`、`hasActed` 和消息必须与预测 preview 一致。
6. 若移动后技能因真实状态变化不再合法，只能按明确 fallback 停在落点/正常结束该单位行动边界；不得直接修改冷却、恢复值或执行另一个未预测的复合命令。

不得让预测 helper 调用真实 mutating `moveUnit` 作用于原 state；允许在 forecast 副本中精确模拟。

### 5. AI 作战计划使用落点 preview

- `aiPlanStepReport` 对 `.useSkill` 根据同一个 `AIIntent.destination` 调用上述唯一 capture-aware projected-state helper，并从同源 preview 读取 `skillSummary` 和 detail；不得另写一个不处理占城/战役结束的简化重建器。
- `AIPlanStepReport.origin` 保持真实起点，`destination` 是施令落点，target position/ID 与 preview 目标一致。
- 不再使用原位置 `formation.skillSummary` 伪装移动施令效果；formation role/readiness 可继续来自现有报告，但技能效果文案必须来自落点 preview。
- `AIOperationalPlanReport.kind == .commanderSkill`、commanderUnitIDs、step 顺序和其他计划类型旧语义保持。

### 6. 敌将威胁与地图范围使用落点 preview

- 私有 `enemyCommanderThreatReport` 在 `intent.kind == .useSkill` 且有 destination 时，调用同一个 capture-aware projected-state helper 取得该 destination 对应 preview；原地技能则自然得到原位 preview，非技能 intent 保持既有 fallback。不得另写第二套落点投影。
- `EnemyCommanderThreatReport.position` 仍为敌将真实起点；`destination` 为 AI 意图落点。
- 下列字段必须全部来自同一个落点 preview：
  - `projectedRecovery`
  - `projectedFortificationReduction`
  - `affectedUnitIDs`
  - `affectedCityIDs`
  - `rangePositions`
  - `affectedPositions`
  - `skillReady`
  - `skillSummary`
  - `skillBlockedReason`
- target unit/city/position、impact、reasons、detail 也必须引用该 preview，不能混入原位值。
- `EnemyCommanderThreatSummary`、`EnemyCommanderThreatMapOverlay` 和 `BattleMapView` 不增加规则计算；继续沿 report -> summary -> overlay 同源链展示起点、落点、技能范围、影响区和目标线。
- 保留 v0.64-v0.68 active/focused/primary、地图 display context、图例、HUD、命令坞和全局 primary 语义。

### 7. 冷却、无落点和稳定 fallback

- 冷却中、已行动、无将领/trait、没有有收益预览时，不产生移动技能候选。
- 没有合法 reachable 落点时保持现有原地技能/攻击/固守/推进/整备 fallback，不崩溃、不产生地图外 destination。
- 不能穿过水域/占用格/外交保护，也不能为了技能绕过 `reachablePositions` 和 `moveUnit`。
- 原地有收益时无条件保持现有原地技能分支，不与移动候选比较；仅原地无收益且不存在直接攻击时，才允许生成移动施令 destination，且选择稳定。
- 同一状态重复调用 `aiIntents`、计划和敌将报告必须得到相同 destination、目标、preview 字段和顺序。
