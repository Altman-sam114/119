# v0.60 AI 集火协同与交战记忆

## 版本号与分配依据

## 背景

《大征服者：罗马》的 AI 会围绕同一目标组织多单位连续打击。当前 `performSimpleAI` 按 `aiActingUnitIDs` 逐个行动，`bestAITarget(for:)` 只做单兵独立评分，各军团互不知晓本回合已交战目标，火力容易分散到多个满血目标上，难以形成歼灭。

已有基础：`aiAttackScore` 中 `damage >= defender.health` 有 +160 击杀加成，说明「打残血目标」价值已被建模，但只有当伤害足以击杀时才生效；两次攻击协同压血的中间态没有奖励。

## 目标

1. `performSimpleAI` 在单回合内维护交战记忆（本回合已被本阵营攻击过的目标 ID 集合）。
2. 目标选择对「已交战且仍存活」的目标施加集火加成，使评分接近时多单元收敛到同一目标，优先歼灭而不是分散骚扰。
3. 击杀已确认（目标被消灭）后不再影响后续评分（死亡目标自然离开 `attackTargets`）。
4. 新增 Swift Testing 用例锁定集火行为；既有 AI 意图预测、主攻优先、伤害一致性测试全部保持不变。

## 非目标

- 不改变 `aiIntents` 意图预测的静态评分（意图是无状态只读预测，加入回合内记忆会破坏「意图伤害与预览/结算一致」的既有测试链路）。
- 不改变 AI 招募、休整、技能、姿态、移动评分逻辑。
- 不改动 UI、地图、readout；本轮是纯核心 AI 行为轮。
- 不新增存档字段（交战记忆是回合内局部变量，不进入 `GameState` 持久状态）。

## 实现步骤

1. `bestAITarget(for:)` 增加带默认值的参数：`bestAITarget(for unit: ArmyUnit, favoring engagedTargetIDs: Set<String> = [])`；评分时对 `engagedTargetIDs.contains(defender.id)` 的存活目标加集火加成（建议 +55，低于击杀 +160、高于罗马 +45，保证「能击杀谁就打谁」优先级不变）。
2. `performSimpleAI` 中维护 `var engagedTargetIDs: Set<String>`；每次 `performAIAttack` 前把 defender id 记入集合；移动后补攻击同样传入并记录。
3. 保持 `aiIntents` 调用路径不变（默认参数空集合，不影响预测）。
4. 新增测试 `aiFocusFireConvergesOnEngagedTarget`：构造两支 AI 军团面对两个评分接近的目标，断言第二支军团选择第一支已交战的目标；再构造目标已被歼灭场景，断言后续单位正常选择剩余目标。
5. `Tools/verify_project.mjs` core token 追加 `engagedTargetIDs`。
6. `.github/workflows/ci-results.yml` `CI_VERSION` 提升到 v0.60。
7. 文档：README 特性行（AI 集火协同）、`md/flow/flow.md` AI 执行流补充交战记忆、`md/test/test.md` v0.60 门禁行、`md/prompt/README.md` 最新指针、`update_log.md` 由 Agent C 验收后补记。

## 风险与禁止项

- 风险：集火加成过高可能翻转「击杀优先」或既有测试的目标选择；+55 低于击杀加成且测试场景需验证边界。若云端既有测试失败，退回调低加成而不是改旧测试。
- 禁止：把交战记忆写入 `GameState` 持久状态或存档；禁止改动 `aiIntents` 预测评分；禁止修改既有测试断言来迁就新行为；禁止本轮夹带 UI 改动。
