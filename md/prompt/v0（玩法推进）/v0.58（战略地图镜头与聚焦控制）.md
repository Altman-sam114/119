# v0.58 战略地图镜头与聚焦控制

## 版本号与分配依据

- 版本号：`v0.58`。
- 分配依据：`update_log.md` 当前最新正式版本为 v0.57；本轮是独立、可云端验证的地图交互版本，因此顺延一个小版本。
- 总目标对应关系：继续把原创 SwiftUI 罗马战棋推进为地图主导、边缘控制、就地选中与命令响应清晰的战略战斗界面；本轮只解决地图镜头操作，不用结构整理代替业务体验推进。

## 背景

v0.52-v0.55 已完成地图主导壳层、原创战略材质和命令层级，v0.56-v0.57 已拆分 `BattleView` 与 `GameViewModel` 的稳定源码边界。当前 `WarMapView` 仍把整张地图固定适配到容器，玩家不能放大观察城市、军团、路线和威胁叠层，也不能拖移或快速把当前选择带回视野。公开官方页面提炼出的参考规律是地图占主体、镜头围绕当前军团或城市、顶部资源带薄且高频控制贴边；只能吸收信息层级与交互规律，不得复制《大征服者：罗马》的品牌、截图、人物、图标或其他素材。

## 本轮目标

1. 为 `WarMapView` 增加统一的纯展示镜头状态，支持缩放、拖移、聚焦当前选择和复位。
2. 地貌底图、路线、六边格、城市、军团、目标环和攻击入口必须共享同一个 camera transform，空间关系不能分层漂移。
3. 顶部战况带、底部地图情报坞和地图镜头工具必须保持在屏幕坐标系，不随地图缩放或拖移。
4. 选中新的格子、城市或军团后，镜头以克制动画把该位置带向可用地图工作区中心；初次云端截图不得因预设选择产生不可预测的入场动画。
5. 增加熟悉的 SF Symbols 镜头控制，至少包含聚焦当前选择与复位；缩放必须同时有触控手势和可发现的按钮入口，并提供无障碍标签、提示与稳定 44pt 点击区域。
6. 为镜头边界与聚焦数学增加 RenderBattlePreview 云端断言，并继续保留三尺寸六图视觉回归。

## 非目标

- 不修改 `GameState`、核心战斗、移动、攻击、AI 评分/执行、敌军意图、任务、经济、外交、存档结构或存档兼容性。
- 不把镜头状态持久化，不新增跨语言层或 Unity 工程；遵循现有 Unity 迁移分析结论。
- 不重做地图材质、军团/城市 token、战斗抽屉、底部命令坞或完整动画系统。
- 不复制、下载或提交《大征服者：罗马》的任何受保护素材。
- 不引入第三方框架，不创建新分支或 PR，不提交人工已有的 Xcode 用户状态、工程文件改动或 `md/unity分析/` 未提交内容。

## 当前架构依据

- `RomeLegionsApp/Views/BattleMapView.swift` 的 `WarMapView` 持有地图渲染层，所有路线、格子和单位已共享 `HexMetrics`，适合在该视图内建立统一内容层与本地 `@State` 镜头。
- `RomeLegionsApp/Views/BattleViewStyles.swift` 的 `HexMetrics` 负责地图拟合与六边形坐标；镜头纯值数学应与其相邻维护，供 SwiftUI 和 RenderBattlePreview 共用。
- `GameViewModel.focusedPosition` 已统一反映普通选择、反制聚焦和目标线聚焦。镜头只观察该位置，不得反向改变规则状态或另造选择源。
- `BattleView` 外层拥有顶部资源带、右上抽屉工具和底部命令坞；地图镜头不能改变这些壳层组件的几何关系。
- `Tools/RenderBattlePreview/main.swift` 已渲染 932x430、390x844、1024x768 三种尺寸并做策略/像素门禁，适合增加确定性的 camera 数学断言，不依赖自动执行真实手势。

## 实现步骤

1. 在 `BattleViewStyles.swift` 增加独立、可比较的地图镜头纯值类型，例如 `MapViewportState`：
   - 默认 `scale = 1`、`offset = .zero`；缩放范围建议稳定在 `1.0...1.8`。
   - 提供缩放、拖移、聚焦和复位方法；所有入口共用同一套 clamp。
   - 拖移范围必须根据容器和当前 scale 限制，不能把地图完全拖出工作区；回到 1x 时 offset 必须归零。
   - 聚焦计算必须考虑以容器中心为锚点的 scale transform，把目标位置移向地图可用工作区中心，并在边缘处正确受限。
2. 在 `BattleMapView.swift` 把 `MapBackdropView`、路线层、格子、攻击入口和目标环包进同一个地图内容层，对该层统一应用 `scaleEffect` 与 `offset`；HUD、情报坞和镜头按钮放在 transform 外。
3. 增加 `MagnificationGesture` 与 `DragGesture`，使用手势开始时的基准 scale/offset，避免连续更新时累计漂移。拖移与格子点击需要共存：轻点仍调用现有 `viewModel.selectTile`，只有实际拖移才改变镜头。
4. 观察 `viewModel.focusedPosition` 的后续变化并执行克制的聚焦动画。首帧只记录当前选择，不自动改变默认 camera，确保 RenderBattlePreview 初始六图稳定；用户选中新位置、反制落点或目标线阶段后才聚焦。
5. 在地图左侧或其他不与右上抽屉工具、顶部战况带、底部情报坞冲突的位置增加紧凑镜头工具。使用 SF Symbols 图标按钮；至少提供放大、缩小、聚焦选择、复位，禁用状态、无障碍 label/hint 和 hover help 完整。小尺寸上不得让文本或按钮遮挡地图主要读板。
6. 在 `Tools/RenderBattlePreview/main.swift` 增加独立镜头策略断言，至少覆盖：默认态、上下限 clamp、放大后可拖移、1x offset 归零、中心目标聚焦、边缘目标聚焦受限、reset 恢复默认。新增明确的 `PreviewRenderError` case。
7. 更新 `Tools/verify_project.mjs` 的必要结构 token，让云端确认镜头值类型、手势、聚焦和复位入口存在；不要把字符串门禁当作真实编译或行为验证。
8. 同步 `.github/workflows/ci-results.yml` 的 `CI_VERSION` 为 `v0.58`，并同步 README、AGENTS、flow、flowchart、test、prompt README 与 update log 的当前真实行为和云端验收口径。

## 验收标准

- 地图支持 pinch/buttons 缩放和放大后的拖移，所有地图空间层保持严格对齐。
- 新选择会把目标带回可用地图工作区；聚焦和复位按钮行为明确，reset 恢复 1x/零偏移。
- 地图不能被完全拖出视口，缩放上下限稳定；连续手势没有明显跳变或累计漂移。
- 地图格点击和攻击入口仍可用，镜头手势不会误触规则命令。
- HUD、抽屉工具、镜头工具、情报坞与命令坞保持固定且三尺寸无不合理重叠。
- 没有修改玩法核心、AI、存档或第三方依赖。
- 最新 `origin/main` 对应的 GitHub Actions 全部成功，artifact manifest/JUnit/log/六图经 Agent C 复判通过。

## 风险与禁止项

- 风险：SwiftUI modifier 顺序会改变 scale/offset 坐标含义；camera 数学必须与实际 `scaleEffect` 锚点一致。
- 风险：`DragGesture` 可能吞掉格子轻点；必须使用合适的组合方式并由云端编译、Render 门禁和人工交互语义共同约束。
- 风险：自动聚焦可能让初次截图或恢复视图时跳动；必须区分首帧同步与后续选择变化。
- 风险：镜头工具可能与现有右上抽屉工具或地图 HUD 重叠；三尺寸六图必须复判。
- 禁止把 camera 状态写进 `GameState` 或存档，禁止在 SwiftUI 手势里复制玩法规则。
- 禁止提交用户现有 `project.pbxproj`、`UserInterfaceState.xcuserstate` 或 `md/unity分析/` 改动。
- 禁止本地验证、伪造测试通过、使用旧 artifact 或非 `Altman-sam114` 账号冒充验收。
