# v0.66 敌将焦点指挥卡与地图命令上下文

## 版本号与分配依据

- 版本号：v0.66。
- 分配依据：v0.65「敌将威胁聚焦同源读板」已在 origin/main 最新提交 60fb1cf8ac9ff4967e041ea075c5009bfa1efa78 完成云端验收；其上游 v0.64/v0.65 已建立 EnemyCommanderThreatReport、EnemyCommanderThreatSummary、EnemyCommanderThreatMapOverlay、focusedEnemyCommanderThreatID、activeEnemyCommanderThreatSummary 和双敌将预览夹具。本轮是 v0.65 之后的下一轮 UI/指挥上下文推进，不重复实现威胁评分、地图范围、影响格、路线或 active summary。
- 本轮目标对应总目标“继续向《大征服者：罗马》推进”的战斗界面层：让地图上已经可以定位的敌将，成为一个稳定、清晰、只读的当前指挥对象；不扩大为新玩法规则。

## 背景

v0.64 建立了核心威胁报告到地图空间叠层的只读链路；v0.65 又让有效 focused threat 优先、否则回退 primary，并让地图空间层、侦察 HUD、顶部敌将 chip、敌情卡和 VoiceOver 使用同一个 active threat id。全局 primaryEnemyEngagementLoopReadout、反制排序和交战桥接仍保留 primary 语义。

当前体验断点是：focusEnemyCommanderThreat 会清空 selectedUnitID 和 selectedCityID，以避免把敌将伪装成本方单位。于是 SelectionCommandDockView 没有单位/城市分支，会退回通用“情报”。玩家看到敌将路线、技能范围、影响格和目标，却在地图底部失去敌将姓名、威胁等级、技能、目标、路线和“仅侦察”上下文；关闭敌情抽屉后断点更明显。

本轮吸收参考游戏“地图为主、底部围绕当前对象给短指挥上下文、详细内容进入抽屉”的信息层级，但只使用本项目原创代码绘制和现有组件，不复制外部截图、素材或项目代码。

## 本轮目标

### 1. 新增唯一的 active 敌将焦点 ViewModel 派生读板

在 GameViewModel 增加纯派生的 activeEnemyCommanderThreatFocusReadout；数据结构放入 GameViewModelStrategyReadouts.swift 的敌将派生域，组装仍由 GameViewModel 提供。不要新增 GameState、@Published、Codable 或 SaveStore 字段。

该读板只能复用 v0.65 的 activeEnemyCommanderThreatSummary、activeEnemyCommanderThreatMapOverlay、activeEnemyCommanderThreatID 和必要的 focused id。禁止在 SwiftUI 重新调用 state.enemyCommanderThreatReports、重新排序/评分、重新计算技能范围、复制 EnemyCommanderThreatSummary 或建立第二套威胁报告。

建议字段（可用同等清晰命名，但必须稳定可被结构门禁和 RenderBattlePreview 读取）：

- threatID、overlayID 或等价同源标识；
- 敌将姓名、阵营、trait/技能名称、身份徽标/符号；
- 威胁等级、已有威胁分或等级文案、技能就绪/阻塞状态；
- 起点、目标、目的地/落点、范围、影响格、路线/空间链摘要；
- 目标对象、目标坐标、影响对象或“无直接影响”的明确空态；
- isFocused 或等价状态，当前地图侦察视角；
- compactLabel、detailLabel、accessibilityLabel；
- commandAvailabilityLabel，固定表达“仅侦察，不执行敌将命令”；
- hasExecutableCommand == false 或等价只读门禁字段；
- 仅供定位/更多情报使用的只读状态，不携带命令闭包、不暴露 attack、moveUnit、restUnit、skipUnit、useGeneralSkill action。

所有字段必须来自同一个 active summary/overlay。无有效 active 时返回 nil 或明确空态；不能保留上一个焦点的姓名、坐标、路线或等级。无效 focused id 时允许 active 回退 primary，但不能偷偷改写 focused id；readout 必须能区分“当前已定位 secondary”和“active 回退 primary”。

### 2. 接入底部 SelectionCommandDockView

在 BattleShellControls.swift 的 SelectionCommandDockView、selectionIdentity 和 SelectionDockCommandButtonsView 增加敌将焦点分支：

- 有效敌将焦点时显示敌将身份卡，不再显示通用“情报”或“选择地图目标”；
- 身份卡显示姓名/徽标、威胁等级、技能、目标/路线摘要和“仅侦察”；
- 命令区最多提供“更多情报/打开敌情抽屉”和明确的已定位状态；不能出现攻击、移动、休整、跳过、姿态、训练、任命、技能执行、扩建或招募按钮；
- 更多情报继续调用现有 onShowMore，不新建抽屉系统；如保留定位入口，只能幂等调用现有 focusEnemyCommanderThreat；
- 无焦点时单位、城市、地块和通用情报旧行为保持；
- 遵守 BattleInterfaceMetrics、identity width、横竖屏布局、44pt hit area、现有 SecondaryButtonStyle/DockCommandButton 和 Dynamic Type。窄屏允许换行，不得硬截断姓名、等级、技能、目标或路线。

可在 BattleShellControls.swift 增加局部 EnemyCommanderThreatFocusIdentityView、EnemyCommanderThreatFocusCommandButtonsView，但不要为此修改 project.pbxproj 或引入新文件。

### 3. 接入 BattleMapView 同级地图焦点读板

在 AttackLockMapReadoutView 同级或同一地图焦点容器增加 EnemyCommanderThreatFocusMapReadoutView：

- 只消费 activeEnemyCommanderThreatFocusReadout，不在 View 拼接 summary/report 字段；
- 与现有 active route/position overlay 使用同一 threatID，显示敌将徽标/姓名、等级、技能、目标/路线和“仅侦察”；
- 不新增第二套路线、范围、目标叠层，不改变 enemyCommanderThreatOverlaysByPosition 全量集合；
- 只在有效敌将焦点上下文出现，失效清理后消失或显示明确的 primary 非焦点状态，禁止 stale secondary；
- 遵守固定顶部战况带、右上五类工具/镜头工具、MapIntelligenceDock、攻击锁定 HUD 和底部命令坞层级，不互相遮挡；
- 使用文字、图标、徽标、描边/线型表达身份，不依赖单一颜色，提供完整 VoiceOver 文案。

### 4. 接入 EnemyIntentPanelView / EnemyCommanderThreatCardView

敌情抽屉继续使用 v0.65 active summary/同源 focus readout，禁止重新拼装 threat report：

- 标题、姓名、等级、技能、目标、起点/范围/影响/落点、路线和 accessibility 全部属于同一 threatID；
- 当前 threat 已聚焦时定位按钮显示“已定位”或等价状态；重复点击幂等、不产生命令；
- 未聚焦时保留“定位敌将”入口；至少 44pt，VoiceOver hint 明确只查看威胁，不执行技能或改变战局；
- 关闭抽屉后底部命令坞和地图焦点读板仍保留同一 threat 身份；
- 卡片和底部卡共享同一个 focus readout 字段/文案，不从不同来源分别拼接姓名、目标或路线。

### 5. 保持全局 primary 与当前 active 边界

逐项审计 primaryEnemyEngagementLoopReadout、selectedCommanderOpportunityBridgeReadout、selectedUnitOrderWindowReadout、mapReconPerspectiveHUDReadout：

- 明确属于全局首要敌情、反制排序、全局交战闭环的继续使用 primary；不得机械替换所有 primary；
- 明确属于当前聚焦敌将身份的地图/底部/敌情上下文使用 active focus readout；
- 若某桥接读板同时展示 global primary 和 current focus，必须拆出字段/标签或保留清楚 source id，不能标题来自 A、enemyCommanderThreatID/路线来自 B；
- v0.65 primary 兼容 API、全量 overlay 位置索引、active fallback 行为保持；本轮不改 AI、反制或全局 readout 评分/排序。
