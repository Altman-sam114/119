## 唯一主目标

将现有

CountermeasureReport -> CountermeasureSummary -> CountermeasureCommandPreview -> 地图 overlay/反制卡/命令坞

接成一个“本方军团反制决策确认闭环”：玩家从同一个反制预览中查看回应军团、推荐姿态、落点、目标、收益/风险和下一步骤，然后分别确认已有的姿态、移动落点或攻击目标锁定入口。

本轮的成功标准不是自动完成一条命令链，而是让玩家在地图主导界面中清楚知道“现在确认哪一步、确认后会发生什么、下一步是否仍可用”，并且每个确认只调用既有单一命令入口。反制 context 必须是纯 GameViewModel 派生状态和 UI 友好文案，不是新的核心规则状态。

## 当前架构依据与边界

### 核心层、ViewModel 层与 View 层

- RomeLegionsCore 继续只负责玩法规则和结算。
- GameViewModel 继续持有 GameState，管理选择态、焦点态、命令入口和 UI 派生读板。
- GameViewModelMapReadouts.swift、GameViewModelStrategyReadouts.swift、GameViewModelSelectionReadouts.swift 只承载 UI 友好派生类型；新增 CountermeasureCommandContextReadout 可放在 GameViewModelMapReadouts.swift 的反制域，或放在最贴近现有反制 readout 的 ViewModel 派生文件中，但仍由同一个 GameViewModel 组装。
- BattleMapView.swift、BattleShellControls.swift、BattlePanels.swift 只消费 readout、展示状态和触发 ViewModel 方法；复杂报告、评分、路径和命令组合不得写进 View。

### 当前反制 source 与 active/focused 语义

当前报告和预览的源链必须保持：

    GameState.countermeasureReports(for: .rome, limit: 5)
        -> GameViewModel.countermeasureSummaries
        -> countermeasureCommandPreviews
        -> current focused preview or primary preview
        -> CountermeasureMapOverlay
        -> map / CountermeasureCardView / SelectionCommandDockView

建议提供下列纯 ViewModel 派生 API，命名可等价但必须具备同等可审计语义：

- activeCountermeasureCommandPreview：有效 focusedCountermeasureID 对应当前 preview 时使用 focused；无有效 focus 时使用 primary。无效 focus 可以回退 primary，但必须通过 isPrimaryFallback 或等价字段表明这是 fallback，不能偷偷改写 focusedCountermeasureID。
- activeCountermeasureMapOverlay：由 active preview/summary 构造；保留 primaryCountermeasureMapOverlay、countermeasureRouteSegments、countermeasureOverlaysByPosition 等旧 primary API，不能为了 active 显示而改变全局 primary 读板。
- activeCountermeasureCommandContextReadout：唯一给地图焦点、反制卡和底部命令坞消费的 readout。无有效 summary/preview 时返回 nil 或明确空态，绝不能保留上一次 focus 的单位、落点、目标、路线、收益或风险。

如果当前选择态 selectedCountermeasureCommandPreview 与全局 focused preview 的关系有歧义，必须先在 ViewModel 中定义并通过运行时门禁锁定：响应单位有效且等于当前 selected unit 时可以作为当前命令对象；否则 context 仍以 focused/primary preview 为源，并明确 isFocused、isPrimaryFallback 和 source ID。不能让命令坞、地图和反制卡分别自行选择不同 preview。

## CountermeasureCommandContextReadout 同源字段

新增 CountermeasureCommandContextReadout 或等价类型必须是纯派生、不可携带复合动作的数据结构。它至少应有以下字段，字段名可调整但不得丢失语义。

### 身份与 source

- id 或 contextID。
- countermeasureID/reportID。
- previewID。
- overlayID。
- sourceID 或等价统一标识，且能证明 preview、summary、overlay 属于同一反制报告。
- isFocused、isPrimaryFallback、focusedCountermeasureID 的可审计语义。
- selectedPerspective 或等价地图视角，反制定位后应为 .countermeasure。
- isReadOnlyPreview、isSingleStepConfirmation 或等价标记。
- context 不得携带命令闭包、GameState 引用、命令队列或 View。

### 本方回应军团

- responseUnitID。
- 本方军团姓名/兵种/将领/徽标文案。
- 当前坐标和当前位置文案。
- responseIdentityLabel、responseDetailLabel、accessibilityLabel。
- 当前是否仍属罗马、是否轮到罗马、是否可选择。
- 不得从另一个 report 或另一个 selected unit 拼接身份。

### 姿态、移动与目标

- recommendedOrder、姿态名称/图标。
- canSetOrder、canConfirmOrder、orderConfirmationLabel、姿态阻塞原因。
- destination、落点文案、canMoveToDestination、canConfirmMovement、movementConfirmationLabel、落点阻塞原因。
- target unit/city ID、target position、target label。
- canAttackCurrentTarget、canLockTarget、targetConfirmationLabel、目标锁定阻塞原因。
- isExecutableNow、blockingReasons、当前步骤、下一步骤和步骤状态。
- impactLabel、riskLabel、commandChainLabel、nextStepLabel。
- 必须复用 CountermeasureCommandPreview 的已有字段和步骤，不得在 View 再计算 reachablePositions、attackTargets 或 attackPreview。
- hasExecutableCommand 只能表示至少存在一个已有的单步确认入口；它不表示 context 拥有复合执行能力，也不得让 context 携带 action。

### 地图与无障碍

- responsePosition、destination、targetPosition。
- route/space chain 摘要、地图 focus label、路线阶段和目标阶段。
- compactLabel、detailLabel、focusStateLabel、commandAvailabilityLabel。
- VoiceOver label/hint 必须包含 source ID 或可追溯反制身份，明确“确认姿态、前往落点、锁定目标是分开的现有入口”。
- 所有字符串、图标、颜色语义必须来自同一 context，不允许卡片只取 summary 而命令坞只取另一个 preview。

## 数据流与状态流

### 只读数据流

    GameState.countermeasureReports(for: .rome, limit: 5)
        -> countermeasureSummaries
        -> countermeasureCommandPreviews
        -> activeCountermeasureCommandPreview
        -> activeCountermeasureMapOverlay + CountermeasureCommandContextReadout
        -> CountermeasureCardView
        -> SelectionCommandDockView
        -> BattleMapView focus readout / active route

primaryCountermeasureSummary、primaryCountermeasureCommandPreview、primaryCountermeasureMapOverlay 和全局桥接仍然是 primary 来源。只有当前地图、反制卡和命令坞的“当前反制对象”使用 active/focused context；同一个 sourceID 必须贯穿这些 View。

### 定位状态流

1. 点击“定位回应”时调用现有 focusCountermeasure(_:) 或由 ViewModel 暴露的薄封装。
2. 有效定位只改变 focusedCountermeasureID、本方回应军团选择、selectedPosition、selectedMapReconPerspective = .countermeasure 和 banner；不直接修改 GameState。
3. 重复定位同一个 ID 必须幂等；不重新执行命令、不重复消耗行动点、不写入存档。
4. 地图 overlay、地图焦点读板、反制卡、底部命令坞必须立即从同一个 active context 读取。
5. 无效 ID 只显示明确错误或 active primary fallback；不能显示旧 secondary 的姓名、路线、坐标、风险或目标。

### 单步确认状态流

#### 确认姿态

- UI 只调用 GameViewModel 的单步入口；最终只能进入现有 setSelectedTacticalOrder(_:) / state.setTacticalOrder 路径。
- 推荐入口可命名为 confirmCountermeasureOrder()，但它必须验证 active context、selected response unit、canSetOrder 和当前阵营，然后只调用一次既有姿态入口。
- 不得同时移动、锁定目标、攻击、释放将领技能或推进下一步骤。
- 成功后可以保留同一个 focus ID 以显示重新派生的下一步骤，但必须重新读取当前 preview/context；若 source 已失效，清除 stale 或明确 fallback，不得继续显示旧状态。

#### 前往落点

- UI 只调用 ViewModel 的单步移动封装或现有合法移动入口。优先复用 selectTile(_:) 的既有选择/移动路径，或由 ViewModel 统一验证后调用同一 state.moveUnit 入口；不得在 SwiftUI 闭包中直接操作 state。
- 必须验证 response unit、当前阵营、destination、canMoveToDestination、行动状态和当前 selected unit；原地落点不得伪造一次移动。
- 移动确认只移动一次到 context 的落点，不得顺便攻击、切姿态、使用技能或结束回合。
- 移动成功后要么保留同一 source 并重新派生 context，要么按明确策略清理 focus；两者必须在代码注释、Render 门禁和文档中一致，不能保留旧坐标/旧路线。

#### 锁定目标

- UI 只调用现有 focusAttackTarget(_:)；目标进入既有 selectedAttackTargetID 和 selectedCombatForecast 路径。
- “锁定目标”只进入攻击预演，不得调用 attack(_:) 或 confirmSelectedAttack()；地图应显示 AttackLockMapReadoutView，底部显示现有预演和取消入口。
- 目标锁定后必须清除或转换 focusedCountermeasureID，避免反制 context 与攻击预演同时声称自己是当前命令源；旧代码在 focusAttackTarget(_:) 和 cancelSelectedAttackTarget() 的清理语义必须保留。
- 真正攻击确认仍由既有独立攻击确认入口处理。本轮不得把反制卡的“锁定目标”改成直接结算攻击。

### 不允许的复合状态流

以下链路全部禁止：

    确认反制
      -> 自动切姿态
      -> 自动移动
      -> 自动锁敌
      -> 自动攻击/技能/结束回合

每次点击只产生一个已有 action 的预期状态变化。若一次 UI 交互会触发多于一个核心 action，必须停止实现并报告，而不是用门禁迁就。

## primary/focused 边界

### 必须继续使用 primary 的全局读板

逐项审计且保持以下语义：

- primaryCountermeasureSummary、primaryCountermeasureCommandPreview：全局首要反制排序和跨对象概览。
- primaryEnemyEngagementLoopReadout：全局敌情交战闭环。
- selectedCommanderOpportunityBridgeReadout：GameViewModel.swift:2850-2870 已注释为 global primary opportunity，不得被 secondary 反制 focus 污染。
- selectedUnitOrderWindowReadout：GameViewModel.swift:3037-3055 继承全局交战 loop；除非源码能证明语义是当前反制上下文，否则保持 primary。
- 既有 primaryCountermeasureMapOverlay 和兼容的 primary 路线/按位置 API：不得删除或偷偷改变其含义。

### 可以使用 active/focused 的当前上下文

- 当前反制定位后的 CountermeasureCommandContextReadout。
- 反制卡的“已定位回应”、回应军团、推荐姿态、落点、目标和下一步。
- 底部 SelectionCommandDockView 的反制身份/确认入口。
- .countermeasure 地图视角下的 active route、response/destination/target overlay 和地图焦点读板。

如果一个 view 同时显示全局 primary 和当前 focused secondary，必须显式标注两者 source ID/标题，例如“全局首要反制”和“当前定位回应”；不得标题来自 A、落点来自 B、目标来自 C。

- active/focused overlay 若与 primary bridge 混用会导致地图路线、命令坞和将领桥接互相矛盾；所有跨源展示必须有明确 source ID。
- 单步确认若通过一个按钮串联多个 action，会破坏玩家控制和核心规则可审计性；发现任何隐式串联立即停止并报告。
- 移动后 response unit、落点和 route 发生变化时必须重算或清理，不能保留旧 preview；攻击锁定必须切换到现有 attack forecast，而不是同时保留反制和攻击两个当前命令源。
- 新增 focused-countermeasure UI 若侵占地图、固定 HUD、情报坞或命令坞，必须调整布局容器和读板密度，不得降低像素阈值或删除旧图。
- 不得伪造本地测试、云端结果、manifest、artifact、PNG 或 Agent C 结论；不得使用旧 artifact 代替最新 run。
- 不得修改用户保护文件、引入第三方技术栈、改变分支制度、创建 PR 或绕过 Altman-sam114 权限。
