# v0.65 敌将威胁聚焦同源读板

## 版本号与分配依据

- 版本号：v0.65。
- 依据：v0.64「敌将技能威胁地图焦点与空间叠层」已经由 origin/main 的最新云端 run 验收通过。最终文档 commit 为 395466b，相关实现和 CI 修复为 f2c04ac、fda85d2、2fbaf1a；run 为 31299715330，attempt 为 1。本轮不重做 v0.64 的威胁报告、地图 overlay 或聚焦命令，只修复聚焦威胁在各 UI 读板之间没有统一选择源的问题。

## 背景

v0.64 已经建立 EnemyCommanderThreatReport -> EnemyCommanderThreatSummary -> EnemyCommanderThreatMapOverlay 的只读链路，也有 focusedEnemyCommanderThreatID、focusedEnemyCommanderThreatSummary 和敌将定位入口。地图空间层与地图侦察 HUD 已经使用 focusedEnemyCommanderThreatSummary ?? primaryEnemyCommanderThreatSummary。

但当前仍有两类读取语义不一致：

- BattleMapView 顶部战况条约 634 行固定读取 primaryEnemyCommanderThreatSummary。
- BattlePanels 的 EnemyIntentPanelView 约 2903 行固定把 primaryEnemyCommanderThreatSummary 传给敌将卡。

玩家聚焦第二个敌将后，地图范围、地图侦察 HUD 和路线可以显示敌将 B，而顶部 chip、敌情卡仍显示首要敌将 A，威胁等级、技能、起点、目标和无障碍文案因此不再指向同一个 threat id。

另外，GameViewModel 的 primaryEnemyEngagementLoopReadout（约 632 行）、selectedCommanderOpportunityBridgeReadout（约 2805 行）和 selectedUnitOrderWindowReadout（约 3001 行）也读取 primary 敌将威胁。它们有些表示全局首要交战闭环或反制关联，有些可能只是在展示当前聚焦的威胁身份；必须逐项审计，不能为了表面统一而把所有 primary 都机械替换成 focused。

本轮目标是增加一个明确的 active 威胁展示源，使“当前聚焦，否则首要”的语义只存在于 GameViewModel 派生层，并让所有明确属于当前威胁上下文的地图、HUD、chip、敌情卡和无障碍文案共享同一 threat id。全局首要交战、AI 作战计划和反制排序仍可继续使用 primary，前提是它们的标题、source id 和文案都保持全局语义一致。

## 本轮目标

1. 在 GameViewModel 增加 ViewModel-only 的 activeEnemyCommanderThreatSummary（或同等清晰命名）：

   activeEnemyCommanderThreatSummary = focusedEnemyCommanderThreatSummary ?? primaryEnemyCommanderThreatSummary

   无焦点时必须与旧版本的 primary 行为相同；focused id 无效、对应报告消失或当前摘要为空时必须自动回退 primary，不能暴露 stale 焦点或让读板错误地消失。可以增加 active threat id、active map overlay 等派生，但它们只能从已有 summary/overlay 派生，不能重新查询、排序、评分或创建第二套威胁报告。

2. 统一当前威胁上下文的 UI 数据源：

   - BattleMapView 顶部“敌将”战况 chip 使用 active summary。
   - EnemyIntentPanelView/EnemyCommanderThreatCardView 使用 active summary；卡片的将领名、威胁等级、技能、起点、范围、影响、目标、目的地和 accessibility label 必须属于同一个 active threat id。
   - 地图 overlay、路线、地图侦察 HUD、图例、定位标题、banner 和相关 VoiceOver 文案的威胁身份保持同源。现有地图位置集合包含全量 threat overlay 的行为不得被 active 替换破坏；active 只决定当前焦点/读板身份。
   - active 为空时，相关 chip、卡片和标签自然隐藏或显示既有空态，不得显示上一次焦点的身份。

3. 审计已有桥接读板的语义：

   - primaryEnemyEngagementLoopReadout 若表示全局首要敌路、战线压力、敌将、反制和响应军团的首要闭环，应继续使用 primaryEnemyCommanderThreatSummary；所有 enemyCommanderThreatID、标题、风险、下一步和 compact/detail/accessibility 字段必须继续来自同一个 primary 闭环。
   - selectedCommanderOpportunityBridgeReadout、selectedUnitOrderWindowReadout 和其他包含敌将字段的读板，只有在明确展示“当前聚焦威胁”时才使用 active；若它们展示的是全局首要反制/交战关联，应保留 primary，并在结构/运行时断言中锁定这一决定。
   - 不允许出现 source id 指向敌将 A、可见标题却显示敌将 B 的混合读板。需要跟随 active 的读板必须让 enemyCommanderThreatID、身份标题、compactLabel、detailLabel、风险和无障碍文案全部由同一个 active 派生源生成。

4. 保持 v0.64 聚焦状态边界：

   - focusEnemyCommanderThreat(_:) 的有效、重复、无效路径、banner、selectedPosition、selectedMapReconPerspective 和互斥焦点清理行为保持不变。
   - 选择单位、选择格、聚焦攻击目标、聚焦反制、聚焦目标线阶段、真实命令结算、endTurn、start(mode:) 和战役重开必须继续清理失效的 focused id；active 不新增持久状态。
   - active 只读用于 UI 派生，不写入 GameState、SaveStore、JSON 存档、AI 输入或命令执行状态。聚焦敌将不能暴露本方 useGeneralSkill、attack 或 moveUnit 的可执行入口。

5. 保持 UI 可读性和可访问性：

   - 顶部 chip 与敌情卡在窄屏、横竖屏和 Dynamic Type 下可以换行，不截断 active 将领身份、威胁等级和关键空间链路。
   - 定位按钮保持至少 44pt 命中区、现有 SecondaryButtonStyle 和 v0.64 VoiceOver hint；按钮只调用 ViewModel 聚焦命令。
   - 使用文字、图标、形状或线型辅助区分 threat id，不能只依赖颜色。不得让 active 读板遮挡固定顶部 HUD、地图镜头工具、底部情报坞或命令坞。

## 风险与禁止项

- 机械替换所有 primary 会把全局首要反制/交战闭环错误绑定到 focused，造成路线、风险、下一步和 source id 不一致；每个引用必须有明确语义决定。
- primaryEnemyCommanderThreatMapOverlay 当前实现虽名为 primary，实际使用 focused ?? primary；若新增 active 别名，必须保留兼容入口和旧断言，不能削弱全量 enemyCommanderThreatOverlaysByPosition。
- 第二 threat fixture 可能改变威胁排序、AI 报告、反制内容或截图像素；优先复用已有多 threat 数据，新增时只改预览副本并保留 carthage-commander、攻击预演、反制和六图旧断言。
- focused id 对应报告消失时若不回退，会显示 stale 将领、空卡或旧地图位置；active 必须是纯派生，不能写回选择源。
- 标签过长、窄屏和只靠颜色会导致 chip/card/HUD/VoiceOver 错配；复用现有文本指标、图标/文字/线型语义并由云端截图复判。
- 禁止引入 Unity 或第三方框架，禁止删除/回滚 v0.60-v0.64 代码、测试、工具、文档，禁止跳过 Agent C 最新 artifact，禁止伪造本地或云端测试通过。
