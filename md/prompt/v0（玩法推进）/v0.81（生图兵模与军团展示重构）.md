## 目标与非目标

- 使用内置生图工具生成原创透明底军团、弓兵、骑兵、战舰四类资源，统一俯视角度、上左光、铁甲/青铜/皮革材质与小尺寸轮廓；资源必须进入真实 App 包，不能只存在于生成缓存。
- 地图优先使用新兵模，阵营由实时地面环和军旗表达；保留兵种、生命、经验、将领、姿态、冷却与行动标记。不以整图染色损害材质，也不把美术资源当作阵营状态源。
- 把军团展示区分为地图、紧凑命令和情报检视尺度；统一使用同一资源映射，提升选中对象和情报面板的真实兵模展示。
- 保留旧 Canvas 兵模作资源缺失时的安全降级；正式云端验收必须确认四类新资源都存在、可解码、有真实 alpha 且已打入 App，不允许 fallback 掩盖资源漏包。
- 不改核心规则、AI、将领数值、ViewModel、存档、地图拓扑与镜头。城镇/地形和整体 HUD 的进一步美术提升属于后续轮次，不能借此缩小人工总目标。

## 当前架构与实现步骤

1. `BattleMapView.swift` 的 `ArmyMiniatureView` 当前用 `BattlefieldMiniaturePainter` 画几何人形；`UnitTokenView` 负责真实状态标记，并被地图、命令坞和情报面板复用。保持这一单向关系，不在美术层增加状态或命令。
2. 保存四类 PNG 至 `RomeLegionsApp/Resources/BattleUnitArt/`；在 `md/art/` 保存来源、实际生成提示词、限制和后续美术差距。原始生成缓存保持不删。
3. 在共享样式编译单元中增加纯资源目录和缓存，以 ImageIO 一次性解码受限尺寸的 CGImage；iOS 只从 App bundle 读取，独立 macOS 云端 Render 通过显式 `ROMELEGIONS_ART_ROOT` 指向同一目录。不新增第三方、网络下载或 body 内反复解码。
4. `ArmyMiniatureView` 组合透明贴图、动态阵营环/军旗，缺失时复用原 Canvas；`UnitTokenView` 使用小型展示尺寸枚举区分地图/命令/检视，不迁移规则或命令。命令坞 44pt 行高和原 102pt 竖屏上限不变。
5. 资源必须加入 Xcode Resources。工程文件已有人工未提交的签名/排序改动：只追加本轮 folder reference/build file/resources member，完整保留原改动，并仅暂存本轮新增 hunks，严禁把人工修改打进本轮提交。xcuserstate 和 `md/unity分析/` 不动。
6. Render 增加四类资源解码、alpha、可读轮廓、映射唯一性门禁，输出一张四兵种/五阵营检视图；保留原三尺寸五上下文 15 张战斗图和全部既有断言。Xcode 云端 build 后核对四类 PNG 实际打包内容。
