# v0.64 敌将技能威胁地图焦点与空间叠层

## 版本号与分配依据

- 版本号：v0.64。
- 依据：v0.63「战斗目标锁定身份与取消入口」已经由最新云端 run 验收通过。本轮不重复攻击锁定/预演，而是把已有敌方将领威胁报告从敌情读板继续落到战略地图空间，作为下一轮 AI、将领和战斗 UI 的边界清晰改进。

## 背景

当前核心层已经有 `EnemyCommanderThreatReport`：它只读聚合敌方将领 trait、将领技能预演、AI 意图、AI 作战计划、战线压力和威胁热区，提供将领坐标、目标坐标、目的地、技能范围、受影响单位/城市、技能状态、影响和反制关联。`GameViewModel` 也已有 `enemyCommanderThreatSummaries`、敌情交战闭环、敌将 chip、敌将卡和反制卡。

但这些信息目前主要停留在文字层：玩家能看到“汉尼拔的攻城布阵/危险/目标”，却不能在地图上同时判断敌将站在哪里、技能能覆盖哪些格、实际影响哪个目标，以及反制地图路线如何对应这条威胁。敌情抽屉也缺少一个可定位到敌将空间的明确入口。这样会让 AI 预判像一张脱离战场的报告，不像《大征服者：罗马》里可直接读懂的战场威胁。

本轮只把既有只读报告做成可定位、可视化、可访问的地图链路：敌将位置 -> 技能范围 -> 受影响格/单位/城市 -> 意图目标 -> 反制入口。不要新增另一套评分、目标筛选或技能规则。

## 本轮目标

1. 新增 ViewModel-only 的敌将威胁地图派生层（建议命名 `EnemyCommanderThreatMapOverlay`，具体命名可按现有代码风格调整），唯一数据源是 `EnemyCommanderThreatReport` / `EnemyCommanderThreatSummary`。至少表达：
   - 敌将/军团起点坐标与身份；
   - `rangePositions` 技能范围；
   - `affectedPositions` 及受影响单位/城市（为空时仍保留技能范围和 `targetPosition`）；
   - 意图目的地/目标坐标；
   - 技能是否就绪、技能名、威胁等级、影响文案和无障碍标签。
2. 将首要或当前聚焦的敌将威胁落到地图叠层：范围使用与本方技能不同的低透明紫色/靛色范围信号，受影响格/目标使用文字或图标、虚实线/焦点环等非颜色信号，敌将起点和目标不可只靠颜色区分。叠层必须与现有六边格、镜头 transform、敌军意图路线、热区/控区和反制路线保持同一地图坐标系。
3. 增加明确的“定位敌将/查看敌将威胁”入口。敌情抽屉的 `EnemyCommanderThreatCardView` 至少提供一个 SwiftUI `Button`（命中区不小于 44pt），调用 `GameViewModel` 的聚焦方法（建议 `focusEnemyCommanderThreat(_:)`）。该方法只更新选择态、焦点 ID、`selectedPosition`/镜头上下文和 banner；不得发动技能、移动、攻击、反制或修改 `GameState`。
4. 聚焦后要能追踪同一威胁链：地图侦察视角切到敌路或保留当前敌情上下文；地图 HUD/图例、敌将卡和无障碍文案都能说明“敌将身份 + 起点 -> 技能范围/影响 -> 目标坐标 + 下一步反制”。清除、切换单位、攻击锁定、目标线/反制聚焦、回合切换或战役重开时不得残留失效的敌将焦点。
5. `EnemyCommanderThreatSummary` 的紧凑/完整文案补足稳定空间身份（将领/军团、起点、目标位置、范围格数、受影响对象或“当前无直接受影响对象”），但所有威胁等级、技能预演结果和影响数字仍来自核心报告；不得在 SwiftUI 中重新评分或重算技能范围。
6. 更新地图叠层图例和侦察 HUD 的派生信号，使当前有敌将威胁时能区分“敌路/敌标”和“敌将技能范围/影响区”；非当前侦察视角可以降权，但不能让聚焦的敌将范围、目标或可访问标签消失。保留 v0.53-v0.63 已验收的敌路、反制、目标线、热区、可达、攻击、技能图例与四种视角优先级。

## 当前架构依据

- 核心层 `EnemyCommanderThreatReport`（`Sources/RomeLegionsCore/GameState.swift`）已有 `position`、`targetPosition`、`destination`、`targetUnitID`、`targetCityID`、`rangePositions`、`affectedPositions`、`affectedUnitIDs`、`affectedCityIDs`、`skillReady`、`skillSummary`、`skillBlockedReason`、`threatLevel`、`impact` 等字段。v0.64 应直接消费这些字段；若发现字段语义不足，优先在应用层补充展示派生，不修改规则层。
- `GameViewModel.enemyCommanderThreatSummaries` 和 `primaryEnemyCommanderThreatSummary` 已由 `enemyCommanderThreatSummary(for:)` 组装；`EnemyCommanderThreatSummary` 位于 `GameViewModelStrategyReadouts.swift`，可在此补足位置/范围/影响的稳定标签。
- `GameViewModel` 已持有 `focusedCountermeasureID`、`focusedBattleObjectiveRole`、`selectedMapReconPerspective` 等 ViewModel 选择态；敌将聚焦应沿用这一边界（可新增 `focusedEnemyCommanderThreatID`），并在其他互斥聚焦/选择命令中清理。
- `GameViewModelMapReadouts.swift` 已承载 `EnemyIntentMapOverlay`、`CountermeasureMapOverlay`、`MapOverlayLegendKind`、`MapReconPerspectiveSignalKind` 和地图空间派生类型；敌将范围/影响叠层应放在同一模块或紧邻模块，不在 `BattleMapView` 重新查找单位、城市或计算距离。
- `BattleMapView.swift` 的 `WarMapView` 对底图、六边格、敌军意图路线、反制路线、目标线、热区/控区、可达/攻击/本方技能使用同一个 `HexMetrics` 与镜头 transform；新增敌将空间层必须遵循同一坐标系并保持固定顶部 HUD、右上五类工具和底部命令坞不被地图层遮挡。
- `BattleShellControls.swift` 的 `MapOverlayPresentation` 和情报坞控制四种侦察视角的透明度/图例优先级；敌将范围应有独立图例 kind、当前视角优先级和非当前降权策略。
- `BattlePanels.swift` 的 `EnemyIntentPanelView`/`EnemyCommanderThreatCardView` 已展示敌将威胁，`BattleView`/`BattleShellControls` 已提供固定 HUD 与命令坞。新增入口只能调用 `GameViewModel` 聚焦方法，不在 View 里拼装报告或执行规则。
- `Tools/RenderBattlePreview/main.swift` 已使用 `carthage-hunter` 相邻接敌和 `carthage-commander`（汉尼拔/攻城专家）fixture，已断言 AI 作战计划、敌将威胁、敌情闭环、反制、地图图例和六张 PNG；应在该 fixture 上增加 v0.64 语义/不可变状态/空间叠层断言，保留所有旧断言。

## 实现步骤

### 1. 梳理真实状态链与报告语义

- 先阅读当前 `EnemyCommanderThreatReport` 生成、`enemyCommanderThreatSummary(for:)`、`primaryEnemyCommanderThreatSummary`、`primaryEnemyEngagementLoopReadout`、`MapOverlayPresentation`、`EnemyCommanderThreatCardView` 和地图 `HexTileView` 的真实调用链。
- 明确一个报告中的起点、技能范围、受影响位置、意图目的地、目标位置的优先级。不要从 `AIIntent` 重新计算技能目标；`affectedPositions` 可为空，仍须显示范围和报告的 `targetPosition`。
- 设计稳定的 ViewModel-only `EnemyCommanderThreatMapOverlay` 及其位置/路线派生类型，提供 id、焦点状态、阶段/角色标签、范围/影响/目标集合、路线段和完整 accessibility label。若使用多个位置角色，重叠格需有确定性优先级或叠放策略，不能因字典覆盖丢掉目标/影响信号。

### 2. 增加 ViewModel 派生与聚焦命令

- 在 `GameViewModel` 增加首要/聚焦敌将威胁地图 overlay、位置集合/字典、路线段和图例所需派生字段。所有查找都复用 `state` 和已有 `EnemyCommanderThreatSummary`，不得在 View 中按位置猜敌将。
- 增加明确命令（建议 `focusEnemyCommanderThreat(_ id: String)`），校验 id 仍在 `enemyCommanderThreatSummaries` 中；无效 id 只更新 banner 错误，不改变核心状态。
- 聚焦有效报告时，清理攻击锁定、反制焦点、目标线阶段焦点等互斥 ViewModel 状态，设置 `focusedEnemyCommanderThreatID`、`selectedPosition` 和地图侦察上下文；可选中报告中的敌将单位以复用既有单位身份读板，但不得让本方技能范围/攻击按钮误认为当前可执行命令。若选择敌将会让现有 `selectedGeneralSkillPreview` 产生展示层副作用，必须在应用层明确限制本方技能入口/范围只对罗马当前单位生效。
- 聚焦、重复聚焦、无效聚焦必须幂等且只改变 ViewModel 选择态/banner/镜头上下文。`state`、单位、城市、资源、回合、active faction、AI 意图和 JSON 存档编码全部不变。
- 在 `start(mode:)`、`selectTile(_:)`、`focusAttackTarget(_:)`、`focusCountermeasure(_:)`、`focusPrimaryBattleObjectiveStage(_:)`、真实命令结算和回合清理路径中按现有选择态规则清理失效敌将焦点，避免旧报告继续高亮；不要改变这些命令原有结算语义。

### 3. 对齐敌情卡、侦察 HUD 和图例

- 扩展 `EnemyCommanderThreatSummary` 的空间身份/链路文案。完整卡至少显示将领名、所属军团/坐标、技能状态、范围格数、受影响单位/城市或明确空影响、目标/目的地和下一步；紧凑卡保持可换行、最小缩放和不截断关键身份。
- 在 `EnemyCommanderThreatCardView` 增加“定位敌将”或等价清晰按钮，使用现有 `SecondaryButtonStyle`/共享命中区和 VoiceOver 语义；不要新增 `onTapGesture`。按钮 action 只能调用 ViewModel 聚焦方法。
- 将敌将威胁加入 `MapReconPerspectiveHUDReadout` 的敌路/敌情 signal（建议新增 `.enemyCommander` signal kind 和 `enemyCommanderThreatID` 引用），让 HUD 能说明“敌将技能范围/影响目标”；更新 `BattleShellControls` 的 symbol/tint 映射。保留原敌军路线、交战闭环、反制 signal，不用敌将 signal 替换它们。
- 在 `MapOverlayLegendKind` 增加独立敌将威胁图例（建议 `.enemyCommanderThreat`），更新 `activeMapOverlayLegendItems` 与 `MapOverlayPresentation.isFocusedLegend/legendPriority`。四种侦察视角下：敌路突出敌军意图和敌将威胁，反制保留低对比敌将上下文并突出反制，目标线/热区继续突出各自主层；当前聚焦敌将的起点、范围和目标不能被完全隐藏。

### 4. 落地图空间层

- 在 `WarMapView` 派生当前敌将 overlay/position sets，并传入 `HexTileView` 或独立地图 overlay view；所有坐标用已有 `HexMetrics.center(for:)`，所有层应用现有 `interactiveViewport.scale/offset`。
- 地图视觉至少包含：敌将起点徽标/身份、范围格低透明填充或虚线边界、受影响格/单位/城市的非颜色标记、目标或目的地 scope/箭头，以及必要时的起点到目标/目的地的威胁连线。颜色只能辅助，不能是唯一语义；图标/阶段文字/形状要在小尺寸仍可辨认。
- 地图层必须 `allowsHitTesting(false)`（聚焦入口来自敌情卡/既有按钮），不得抢占六边格、攻击徽标或地图镜头手势。避免全图厚重虚线、紫色大面积遮盖地貌、与敌路/反制路线高对比冲突。
- 与 `selectedGeneralSkillRangePositions` 区分本方和敌方来源；不要因查看敌将而出现可执行本方技能按钮或错误的攻击目标列表。保持既有地图材质、海岸线、镜头上下限、固定 HUD、边缘工具和命令坞。

### 5. 完善云端预览 fixture 与结构门禁

- 在 `Tools/RenderBattlePreview/main.swift` 沿用现有 `carthage-commander` 汉尼拔/攻城专家 fixture，必要时只为使相邻敌城/影响位置确定而调整预览副本城市归属/城防；不得改变真实玩法默认数据或削弱既有 v0.63 攻击 fixture。若调整 fixture，保留 `carthage-hunter`、罗马军团、AI 计划、战线压力、反制和城市读板的旧断言。
- 新增一个专用错误 case（建议 `missingEnemyCommanderThreatMapOverlay`）并在渲染前断言：
  - 首要/指定 `carthage-commander` 报告的 `position`、`targetPosition`、技能范围、技能状态、技能/影响文案非空且能生成 overlay；
  - overlay id 与报告/summary 同源，起点、范围集合、影响集合、目标坐标、路线/角色 labels 和 accessibility 全部一致；范围至少有一个有效地图位置，目标位置落在地图中；若影响集合为空，overlay 明确保留“无直接影响”而不是伪造位置；
  - 地图位置字典/集合不丢失起点、目标或范围重叠信号；图例包含敌将威胁 kind，`MapOverlayPresentation` 四视角优先级符合要求，HUD signal 能引用同一 threat id；
  - 调用 `focusEnemyCommanderThreat` 后 `focusedEnemyCommanderThreatID`、`selectedPosition`/敌将身份（若采用）和 banner 正确，地图上下文可定位；重复聚焦幂等；调用前后 `GameState`、JSON 编码、单位/城市/资源/回合/阵营和 AI 意图快照完全不变；无效 id 不改变核心状态；
  - 聚焦后不允许通过敌将入口调用 `useGeneralSkill`/`attack`/`moveUnit`，本方技能/攻击可执行状态没有被错误替换；清理焦点后继续既有攻击锁定、取消、城市场景和六图断言。
- 渲染单位场景前或后按现有流程显示敌将地图叠层/敌情卡；继续生成横屏、竖屏、宽屏三尺寸和对应 `*-unit.png`，并确保像素门禁没有被改变为只看语义。
- 更新 `Tools/verify_project.mjs` 的必需 prompt、v0.64 结构 token/新入口/新 overlay/新 legend token；更新 `.github/workflows/ci-results.yml` 的 `CI_VERSION` 为 v0.64。不要用静态字符串门禁代替运行时断言。
