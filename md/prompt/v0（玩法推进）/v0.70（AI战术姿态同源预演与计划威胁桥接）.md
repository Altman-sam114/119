## 2. 背景与唯一主目标

当前 `preferredAITacticalOrder` 先根据生命、近敌距离、单个目标和目标距离选择姿态；`aiIntent` 与 `performSimpleAI` 随后分别重新选择行动。
因此姿态并非与最终目标/落点一起比较；已移动单位无法切换姿态时，预测还可能套用不能真实执行的新姿态。
`bestAITarget` 已有击杀硬层，但预览与评分重复计算；`bestAIDestination` 在 sort comparator 内反复调用昂贵的 `aiPositionScore`。
v0.69 已因派生读板反复搜索移动技能候选出现 Render 超时，不能通过四姿态无条件复制整套搜索扩大成本。

本轮建立私有纯值“姿态 + 行动”候选：基于唯一 `CombatPreview` / `GeneralSkillPreview` 比较突击击杀、坚守生存、行军落点。
意图和真实执行共用候选选择语义；作战计划理由、敌将威胁和地图沿已选 intent 复用结果，不各自重新选姿态。
完整链路为：合法姿态集合 → 行动 tier 剪枝 → 预览与候选排序 → AIIntent / 真实命令 → 已选 intent 的计划、威胁、地图读板。

1. 引入语义清楚的私有纯值候选，例如 `AITacticalActionCandidate`，以及唯一选择入口 `bestAITacticalAction(for:favoring:)`；命名可调整。

3. `AIIntent` 由获选候选直接投影；保留现有 kind、destination、target IDs、projectedDamage、threatScore 含义，不把 UI threatScore 当作跨行动 tier 的总分。
4. 未移动且未行动时可比较四种现有姿态；已移动但未行动时只允许当前 `resolvedTacticalOrder`，仍可评估合法原地攻击/技能/休整。
5. 已行动、战役结束、错误行动阵营等状态不得生成可执行候选；真实执行继续保留公开命令的全部 guard。
6. `aiPlanningForecast` 原有“只读下一行动回合刷新”语义保留；刷新仅由明确的预测入口进行，不在通用候选 helper 中偷改 faction/行动标记/冷却。
7. `aiPlanningUnit` 必须继承真实 hasMoved/hasActed；只有模拟合法移动时把 hasMoved 设为 true，不能为获得候选把已行动重置为 false。

9. 姿态可枚举不等于都要搜索落点；先按下一节确定行动 tier，再只展开必要候选。

## 6. 行动 tier 与风险排序

行动层级是不可被高分越过的硬顺序：休整 → 原地有收益技能 → 当前直接攻击 → 移动决策 → 无落点固守 fallback。

1. 先用现有 `shouldAIRest` 判断；满足时不评估更低行动 tier，不改资源、供应和生命阈值。
2. 其次检查原地 `GeneralSkillPreview` 和现有收益判断；有收益原地技能继续优先于直接攻击，包括直接击杀，不擅自反转旧行为。
3. 只有前两层不成立，才在全部合法姿态的当前直接攻击候选中比较；任一直接攻击成立即停止移动搜索。
4. 移动决策内部保留 v0.69 子顺序：合法有收益移动技能优先；没有该候选才进入移动后攻击/夺城/推进/固守落点选择。
5. 对同一攻击 tier 的目标与姿态联合分层：先保留可立即击杀候选；只有不存在击杀候选时才保留非击杀候选。不可用 magic number 代替该层。
6. 在所保留的击杀/非击杀层内先避免 `preview.attackerFalls`；再比较收益与反击风险，之后稳定 tie-break。生存偏好、技能分、集火分均不得提升非击杀到击杀层之上。
7. 攻击收益复用现有 `aiAttackScore` 的目标价值与 engaged 偏好，扣除来自同一 preview 的反击代价；风险权重集中具名、说明尺度，并以坚守生存夹具锁定，不散落新生命/距离启发式决策。
8. 用 `retaliation`、`attackerRemainingHealth`、`attackerFalls`、`defeatsDefender` 解释风险；不复制伤害公式，不把简单距离猜测表述为确定伤亡。
9. 无攻击 preview 的技能/推进/休整候选只比较实际技能收益、已有落点价值、地形/有效防御和局部暴露；暴露若用邻近敌军范围近似，须明确是排序提示而非伤害预测。
10. 行军必须因真实可达格增加或更好的合法目标/落点收益获选，不能仅因“目标远”提前决定；不得牺牲更高行动 tier。
11. 普通移动落点先计算该落点的最佳合法攻击及击杀标志；存在可达移动击杀时，普通移动内的非击杀落点不能靠集火或城市加分反超，不越过移动技能子 tier。
12. 同 tier/击杀/风险收益相等时采用确定性顺序，例如较低反击、较短移动、保留当前合法姿态、固定姿态序、目标 ID、坐标 y/x、unitID；写清顺序并测试，禁止 Set 遍历顺序决定结果。

## 7. 性能：先剪枝，再局部复用

- 休整、原地技能、直接攻击命中后立即返回该 tier 的获选候选；不得预先为四姿态构建整张地图的移动技能候选。
- 无将领、无 trait、已行动、冷却未就绪必须在技能落点 BFS 前剪枝；已移动单位不得搜索新移动落点。
- 一次单位选择调用内，按真实移动预算和通行规则复用 `reachablePositions`；均衡与突击在规则相同的前提下共享集合。
- 坚守/行军预算不同，不能盲用另一姿态的集合；可按不同预算各算一次，或用保留完整移动成本语义的单次搜索派生，勿用 hexDistance 截取假装可达。
- `bestAIGeneralSkillCandidate` 与普通落点评分接收或复用上述局部 reachable，不能每候选再次 BFS。
- 同 destination 下姿态不影响技能效果时可复用 capture-aware 技能投影；有姿态依赖的战斗/防御预览必须分开，不能错误共享。
- 改造 `bestAIDestination` 为先 map 出 `(destination, score, preview/target, rank)`，再用纯数值 comparator 排序或单遍择优；每个有效姿态-落点只评分一次。
- `bestAITarget` 的击杀判断、`aiAttackScore` 和 intent.projectedDamage 复用同一个已算 preview，避免评分函数再计算同一战斗。
- 目标列表、目标距离、合法性和已算候选在单次调用内复用；不要把每个敌方意图/完整 threat heat/全部 plans 嵌入候选评分。
- 不新增跨回合缓存，也不增加公开诊断状态；性能依据为代码调用结构与本轮云端日志耗时，不编造本机 benchmark。

2. `performSimpleAI` 保留招募和 `aiActingUnitIDs` 的威胁降序/unitID 同分顺序，每个单位行动前从当前真实状态选择候选，并传入本回合 engaged 集合。

4. 休整、攻击、移动和技能都调用既有公开命令；不能直接写 health、position、城市归属、行动标记或冷却来模拟结算。
5. 直接攻击、移动落点评分、移动后攻击贯穿同一 engaged 集合；保持其单次真实 AI 回合局部生命周期，不泄露到只读 forecast 或存档。
6. 同一状态/同一 engaged 输入下选择必须一致；后续单位受先前行动影响允许重新选择，不承诺空记忆静态意图等于整轮集火执行。
7. 移动技能继续使用 capture-aware `aiGeneralSkillProjection`：模拟占城、城市归属和战役结束，再由唯一 `GeneralSkillPreview` 判断收益。
8. 真实 `moveUnit` 后检查终局，重新读取单位和唯一 preview，再执行候选对应的攻击或技能；结算失败/目标变化只能按明确合法 fallback 收敛，不自动串接另一复合命令。
9. 若确需重选，只在已变化的真实状态调用同一入口，不能重置 hasMoved/hasActed；无合法尾随动作时安全停止该单位分支。
10. 终局占城不能预测或执行尾随技能/攻击；移动施令不继续攻击，冷却、无收益、无落点、原地技能和条约保护维持 v0.69 全部回归。
