# v0.71 战斗页青铜军令 UI 重构与云端门禁修复

## 版本与范围

- 版本号承接 v0.70，为 v0.71；用户总目标是持续接近《大征服者：罗马》的地图战棋观感，优先改善战斗页 UI 层级、地图可读性和云端迭代稳定性。
- 用户本轮明确要求不要再开子智能体，因此 Agent X 单人完成本轮 A/B 编排与实现；仍必须把 `main` push、GitHub Actions 结果包和最新 run 复判作为完成门槛，不得把本地输出当验收。
- 保护用户未提交的 `RomeLegionsApp.xcodeproj/project.pbxproj`、xcuserdata 和 `md/unity分析/`，不得暂存、回滚、清理或改写。

## 背景

- v0.70 云端 run `34176961101`、attempt `1`、commit `91fbc36725b7e667ef9a988bb09d90274c6f4bff` 的 Swift Testing、Gameplay Smoke 和 Xcode build 成功，但 RenderBattlePreview 在反制姿态单步运行时抛出 `missingCountermeasureOrderRuntimeConfirmation`；Static Checks 还因 `Tools/verify_project.mjs` 只匹配同名公开包装函数，未读到私有敌将威胁实现而失败。
- 当前战斗页已有地图主导布局、五种显示 context、情报坞和命令坞，但顶栏、抽屉、边缘工具和底部军令仍使用分散的黑色半透明样式，青铜/象牙/危险色的视觉语义未集中，难以达到罗马军令台的统一层级。

## 目标

1. 修复结构门禁函数定位，使同名 public wrapper/private implementation 的数据流检查检查实际实现，不放宽门禁。
2. 修复 RenderBattlePreview 的反制姿态运行时 fixture：如果基础场景已处于推荐姿态，在隔离数据副本只改变当前姿态，仍真实调用 `confirmCountermeasureOrder()` 并核对状态、存档、资源、城市、回合、AI intent 和选择态。
3. 新增 `BattlePalette` 共享战斗页视觉 token，重构顶栏、底部命令坞、抽屉、边缘工具和地图情报坞的青铜/象牙/深色层级；保持原尺寸、按钮 action、ViewModel 数据源、五种 display context 和 15 张预览路径。
4. 保持 SwiftUI 只展示状态和触发现有命令，不在 View 中复制规则，不引入图片或第三方框架。

## 非目标与保护行为

- 不新增 `GameState`、Codable、AIIntent、存档字段、命令队列或玩法规则；不改变移动、攻击、技能、姿态、反制、胜负和 AI 评分。
- 不替换地图坐标、镜头数学、叠层来源、地图尺寸策略、交互命中区或现有 accessibility identifier。
- 不修改用户工作区保护文件；不创建 PR、分支或 worktree；不运行本地测试、build、typecheck、Render、verify_project、解析脚本或 `git diff --check`。
