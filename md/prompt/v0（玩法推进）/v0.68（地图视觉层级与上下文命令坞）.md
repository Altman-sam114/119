## 背景与本轮判断

人工总目标是持续向《大征服者：罗马》的战场体验推进，优先优化战斗界面 UI、地图信息层级、AI/将领表达，并在新模型阶段适度重构旧 UI 代码。这里的“推进”只参考其清楚的战略地图层级、当前命令聚焦和信息渐进披露，不复制其美术、截图、名称、布局或受版权保护素材。

本轮审计没有选择继续增加 AI、将领或反制卡片。原因是现有 AI/将领信息并不缺失，真正阻碍玩家的是同一时刻太多信息争夺地图：地图底图、六边格描边、敌军路线、敌将路线、战术建议、目标线、反制线、地块标记、地图侦察坞、焦点 HUD 和底部命令坞都具有较高对比度。继续增加一层读板只会放大问题。

> 建立纯 ViewModel 派生的战场显示上下文，并据此重构地图叠层与底部命令坞，使默认侦察、选中军团执行、攻击锁定、敌将焦点、反制焦点五种状态各自具有一个明确主任务；地图始终是主视觉，非当前路线和详情退到次级或按需抽屉，同时完整保留 v0.67 的同源反制、三个单步确认入口、全局 primary 语义和 15 张云端预览路径。

## 目标

### 1. 建立唯一战场显示上下文

在 GameViewModel 派生层提供 `BattleDisplayContextReadout`、`BattlePresentationContext` 或等价纯值类型，至少能稳定区分：

1. `baselineRecon`：无当前执行焦点，地图按用户选择的侦察视角显示一类主情报。
2. `unitExecution`：本方军团已选中，当前可达、攻击、技能或目标线阶段等可执行/可定位信息为主。
3. `attackLock`：已有 `selectedCombatForecast`，只突出攻击发起者、锁定目标和预演身份链。
4. `enemyCommanderFocus`：有效 `focusedEnemyCommanderThreatID` 与 active readout 同源，突出该敌将威胁路线/目标。
5. `countermeasureFocus`：有效 `focusedCountermeasureID` 与 active context/overlay 同源，突出该反制回应路线/落点/目标。

命名可以调整，但必须有明确优先级。建议优先级为：attack lock > focused countermeasure > focused enemy commander > selected Rome unit execution > baseline reconnaissance。有效性必须由 ViewModel 现有 active/focused/readout 语义判定，不能只看一个可能 stale 的 String ID。

显示上下文只包含 mode、有效 source、面向用户的短标题/状态、当前主要 overlay family、可见 legend kinds、命令坞布局 cue 等 UI 派生信息。不得包含 SwiftUI `Color`、View、闭包、GameState 引用、核心规则、路径重算或命令队列。

### 2. 让地图每个状态只有一个主叙事

`MapOverlayPresentation` 或等价表现模型必须同时消费地图侦察视角和战场显示上下文，再统一决定路线、地块标记、格线、图例和 HUD 的 `primary / secondary / hidden` 层级。

- `baselineRecon`：用户当前侦察视角对应的 enemy intent、countermeasure、objective 或 terrain pressure 为唯一主情报族；其他非交互路线隐藏，或只保留一个确有必要的次级上下文。
- `unitExecution`：reachable、attack target、skill range/target 和明确 active objective stage 等当前交互标记优先；全局敌路/敌将/目标线/反制不得同时以主对比度出现。战术建议若是当前选中军团的直接行动 cue，可作为唯一主路线，否则降级。
- `attackLock`：攻击发起者、目标环、目标按钮和 forecast HUD 为主；敌路、敌将、建议、目标线、反制、热区/控区均隐藏或降到不会干扰确认的背景级。
- `enemyCommanderFocus`：当前 active 敌将威胁路线、作用格和目标为主；若需要敌军 intent 作因果背景，只能作为低对比次级；反制、目标线、建议、热区不得竞争。
- `countermeasureFocus`：当前 active 反制路线、回应位置、落点和目标为主；同源敌将/敌路可作为一个低对比威胁背景，但不能与反制线同权；其他路线隐藏。

建议将主路线/标记的表现强度保持在 `0.75...1.0`，必要次级不高于 `0.22`，hidden 为 0/不建立 View；具体值可按云端图像调节，但必须能通过纯 presentation 断言证明主次差距，不得继续让三类以上非交互路线同时清晰。可执行攻击、技能、可达范围和选中目标不受单纯侦察 perspective 错误隐藏。

普通未选中地块边界必须退为地貌分区辅助，不再形成亮色主网格。城市/单位势力边界、当前选中、可达、技能和攻击目标仍可高亮，但同一格的多层描边应合并、互斥或按上下文降级；不能同时堆叠多个同权六边描边、虚线、圆点和 glow。海岸线、道路、城市、单位和六类地貌必须因此更容易辨认，而不是把地图整体变暗。

### 3. 重构上下文命令坞

在不增加固定 chrome 高度的前提下，将 `SelectionCommandDockView` 重构为稳定的“短身份 + 当前主动作 + 按需详情”结构：

- 横屏/宽屏：身份只保留对象名称、姿态/状态和一个当前 cue；命令组保持视觉主位；命令组右侧不再常驻重复的收益、风险、路线和下一步长文本。详细内容进入现有“更多情报”抽屉或已有对应详情卡。
- 竖屏：使用明确的两行/两区布局，在现有 102pt 上限内让短身份和命令按钮各有稳定空间；不要继续把 128pt 身份列、三个以上按钮、长 detail 和更多按钮全部挤在一个 HStack。不得通过横向滚动隐藏核心命令。
- 反制焦点必须保留 v0.67 的“姿态、落点、锁敌”三个独立 44pt 入口、禁用态和单步语义；当前可执行步骤可获得更强主按钮权重，但其他两个入口仍可发现、可访问，不得合并成自动连招。
- 普通单位必须保留攻击、技能、休整、跳过及既有姿态/更多入口；城市必须保留扩建/招募；敌将焦点继续是只读，不能出现敌方可执行命令。
- MapIntelligenceDock 在 focus/execute 状态只显示当前视角选择、短状态和经过上下文筛选的图例；敌情闭环、风险、完整 legend 等详情继续能在现有抽屉/读板访问。不要删除原始 readout 或 `activeMapOverlayLegendItems` 的全量语义，可增加专供常驻 HUD 的 filtered presentation。
- `BattleInterfaceMetrics.commandDockHeight` 不得高于现有竖屏 102、短横屏 80、普通横屏/宽屏 88；布局必须有稳定尺寸，长姓名、中文、坐标和 Dynamic Type 不得溢出或遮挡相邻控件。

### 4. 消除可见内部 ID，保留同源追踪

- `sourceID`、countermeasure/report/preview/overlay ID、`references(preview:)` 和 `references(overlay:)` 全部保留，v0.67 同源断言不得削弱。
- 新增或调整 `mapTitleLabel`、`mapSpatialLabel`、`commandCueLabel`、`userFacingAccessibilityLabel` 等人类可读派生字段，使可见 Text 只显示“反制定位/回应军团/姿态/落点/目标/下一步”等短文案。
- `sourceLabel`、`mapFocusLabel`、`detailLabel` 若继续存在，必须明确区分 diagnostic 与 user-facing；任何进入 SwiftUI `Text`、按钮 title/value、banner 的字符串不得包含完整内部 source ID。
- 自动化/同源追踪可使用 readout 原始字段、Render 直接断言和 `.accessibilityIdentifier("countermeasure-context-\(sourceID)")` 或等价稳定 identifier。VoiceOver 的可听 label/hint 应是人类可理解内容，不朗读长内部 ID；不能为了修视觉问题删除无障碍身份、动作边界或“不会自动执行后续步骤”的说明。

## 当前架构依据与边界

### 核心层

`RomeLegionsCore` 继续是规则、AI、路径、结算和存档数据的唯一来源。本轮 UI 重构不得修改核心层，也不得让 SwiftUI 推导新的玩法真相。

### ViewModel 派生层

`GameViewModel` 继续管理选择、attack lock、focused enemy commander、focused countermeasure、focused objective stage 和 map recon perspective。新显示上下文由这些现有状态和现有 readout 纯派生：

```text
GameState + selection/focus/perspective
  -> existing summaries/previews/overlays
  -> BattleDisplayContextReadout
  -> map presentation + HUD presentation + command dock presentation
```

适合把值类型放在 `GameViewModelMapReadouts.swift`，由 `GameViewModel.swift` 组装。它不得依赖 SwiftUI Color；颜色、opacity、stroke、布局仍属于 View 表现层。

### View 表现层

- `BattleMapView.swift` 消费 display context 和现有 overlay/readout，建立地图图层、格线层级和焦点 HUD。
- `MapOverlayPresentation` 当前误放在 `BattleShellControls.swift` 顶部；本轮可将其与相关 presentation enum/struct 移到 `BattleMapView.swift` 内的稳定区域，或保留位置但解耦成小纯值类型。不要为了移动它新增工程文件。
- `BattleShellControls.swift` 消费同一 display context，拆出 portrait/landscape 的稳定命令坞布局和 identity/action/detail 子视图。
- `BattlePanels.swift` 的详情卡和抽屉继续作为完整情报来源；仅在必要时接入打开详情或同源 identifier，不做大规模重排。
- SwiftUI `body`、按钮闭包、`onChange` 和 gesture 内不得调用 `state.countermeasureReports`、AI 评分、路径搜索、攻击计算或重新拼装 source chain。

### 显示上下文数据流

```text
selectedCombatForecast
focusedCountermeasureID + activeCountermeasureCommandContextReadout
focusedEnemyCommanderThreatID + activeEnemyCommanderThreatFocusReadout
selectedUnit + focusedBattleObjectiveRole
selectedMapReconPerspective
  -> GameViewModel.battleDisplayContextReadout
  -> MapOverlayPresentation(context, perspective)

  -> SelectionCommandDockView responsive layout
```

同一个 context mode 和 active source 必须贯穿地图主路线、焦点 HUD、图例和命令坞。View 不得各自用不同条件重做 precedence。

### 状态优先级与转换

1. 无选择或城市/普通地块选择：`baselineRecon`，只突出当前侦察视角。
2. 选择本方军团：进入 `unitExecution`；地图优先显示当前可执行范围/目标和必要行动路径。
3. 锁定攻击目标：进入 `attackLock`；forecast 成为唯一当前命令源，countermeasure/enemy/objective focus 按 v0.67 既有规则清理或退级。
4. 聚焦敌将：进入 `enemyCommanderFocus`；只读敌将威胁 source 贯穿地图、HUD、命令坞和敌情抽屉。
5. 聚焦反制：进入 `countermeasureFocus`；v0.67 active context/overlay 贯穿地图、HUD、命令坞和反制卡。
6. 取消攻击、选择其他对象、无效 focus、执行姿态/移动/锁敌、rest/skip/skill、endTurn、start 后，display context 必须由当前状态重新派生，不得缓存旧 mode/source/文案。

显示上下文读取和地图视角切换保持只读，不改变单位、城市、资源、回合、active faction、AI intent、campaign status 或存档编码。现有命令仍只产生各自已有的预期变化。

### primary/focused 边界

- 全局摘要、AI/将领桥接和跨对象读板继续使用 primary。
- 只有当前地图焦点、常驻 HUD、命令坞和对应 focused 卡使用 active/focused source。
- presentation 隐藏一条线不等于删除其数据；切换侦察视角或打开抽屉后仍可访问完整 readout。
- 无效 focused ID 可以按 v0.67 回退 primary，但 display context 必须标记 fallback，不能把 stale ID 当有效 focused mode，也不能在可见文案中留下旧对象。
