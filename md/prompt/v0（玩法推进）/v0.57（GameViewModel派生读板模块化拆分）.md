# v0.57 / GameViewModel 派生读板模块化拆分

## 版本号与分配依据

- 版本号：`v0.57`。
- 分配依据：`v0.56` 已完成 `BattleView` 战斗壳层模块化并通过最新 `origin/main` 云端 artifact 验收，本轮顺延一个小版本。
- 本轮继续落实 `md/unity分析/Unity迁移分析报告.md` 的结论：不为解决 SwiftUI 文件膨胀全量迁移 Unity，先拆分 `GameViewModel`；按人工要求由 Agent X 顺序执行 A/B/C，不启用子 Agent。

## 背景

`RomeLegionsApp/App/GameViewModel.swift` 当前 7,623 行，其中前约 3,994 行是模块级 summary、readout、overlay、route segment 与 UI 枚举，真正的 `GameViewModel` 类从约第 3,998 行开始。地图、AI、将领和命令界面继续迭代时，这些展示模型与状态协调类共处一个文件，会扩大修改冲突、结构检查遗漏和跨域阅读成本。

v0.56 已把战斗视图拆为五个稳定编译单元，本轮应以相同原则拆出纯展示数据类型，为后续继续优化地图、AI 与将领建立清晰边界。不得借结构重构改变现有 UI、算法或玩法。

## 本轮目标

1. 将 `GameViewModel.swift` 中位于 `@MainActor final class GameViewModel` 之前的模块级 UI 派生类型按地图战场、战略态势、选中对象拆成三个编译单元。
2. 保持全部类型名、属性、计算属性、方法、访问级别、初始化方式、文案、无障碍语义和引用关系不变。
3. 让 `GameViewModel.swift` 只保留 import、`GameViewModel` 状态协调类及其现有类内实现，使主文件降至约 3,626 行。
4. 同步 Xcode target、RenderBattlePreview 独立编译清单、SwiftUI typecheck 文档清单和结构检查聚合源。
5. 更新架构、测试、入口与版本文档，并将 workflow artifact 版本提升为 v0.57。

## 非目标

- 不拆分 `GameViewModel` 类体或跨文件移动类内 `private` 方法。
- 不改 `GameState`、AI 评分/执行、路径、战斗、技能、将领、任务、经济、外交、存档或回合规则。
- 不改变任何 summary/readout 的字段、排序、映射、ID、文案、颜色来源、状态流或聚焦行为。
- 不改变 BattleView 五文件的布局、视觉参数、按钮 action/disabled、地图 overlay 权重或无障碍标签。
- 不迁移 Unity，不引入第三方框架、资产、长期分支或 PR 流程。
- 不运行任何本地测试、build、typecheck、RenderBattlePreview、结构验证、`git diff --check` 或解析检查。

## 当前架构依据

- `GameViewModel.swift` 第一个 `@MainActor final class GameViewModel` 之前共有 72 个模块级 `struct/enum`，均为 SwiftUI/UI 友好的只读派生数据载体或展示映射，不持有独立核心规则状态。
- `GameViewModel` 类仍负责 `@Published` 选择态、侦察视角、banner、核心命令与派生数据组装；其私有帮助方法保留在原文件可以避免放宽访问级别。
- BattleView 五个编译单元按内部模块可见类型读取这些 readout，不需要公开 API 或第三方依赖。
- `.github/workflows/ci-results.yml` 的 RenderBattlePreview 使用显式 Swift 文件清单；Xcode 工程也使用显式 PBX file reference 与 Sources phase。
- `Tools/verify_project.mjs` 当前只读取 `GameViewModel.swift` 验证 token，拆分后必须聚合四个 ViewModel 源文件，并要求新文件存在且进入 PBX 工程。

## 实现步骤

1. 新建 `GameViewModelMapReadouts.swift`，移动 `FactionSituation` 起至 `BattleObjectiveMapOverlay` 止的地图、敌情、反制、目标线、侦察视角和战役推进派生类型。
2. 新建 `GameViewModelStrategyReadouts.swift`，移动 `MapControlSummary` 起至 `SelectedUnitSituationReadout` 止的控区、热区、AI 计划、敌将、反制、战线压力和处境派生类型。
3. 新建 `GameViewModelSelectionReadouts.swift`，移动 `LegionFormationSummary` 起至 `SelectedCityBrief` 止的军团成长、将领、军令窗口、姿态和城市派生类型。
4. `GameViewModel.swift` 保留 `import Foundation`、`import SwiftUI` 和完整 `@MainActor final class GameViewModel`；除新文件 import 与编译单元边界空行外，移动内容必须机械等价。
5. 新文件使用原有模块内默认访问级别，不擅自添加 `public`、复制类型或重写计算逻辑。
6. 将三个新文件加入 Xcode App group 和 Sources phase；必须保护 `project.pbxproj` 中人工未提交的 Xcode 格式与签名改动，提交时只暂存本轮 PBX 引用。
7. `.github/workflows/ci-results.yml` 的 RenderBattlePreview 编译清单在 `GameViewModel.swift` 前显式加入三个 readout 文件，并将 `CI_VERSION` 改为 v0.57。
8. `Tools/verify_project.mjs` 将新文件加入 required/PBX token，聚合四个 ViewModel 文件后执行原有 token 检查。
9. README、`md/test/test.md` 中所有 RenderBattlePreview 和 SwiftUI typecheck 示例同步列出三个新文件。
10. 同步 `AGENTS.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/prompt/README.md` 与 `update_log.md` 的当前真实模块边界。

- 风险：`project.pbxproj` 存在人工未提交改动；不得覆盖、回滚或提交人工签名/格式变化。
- 禁止为解决编译问题复制类型、放宽核心状态访问、移动类内 private 方法或改变业务实现。
- 禁止提交 Xcode 用户态文件、Unity 报告、参考游戏素材或无关改动。
- 禁止本地验证、创建 PR/候选分支、伪造云端成功或用旧 artifact 推进 Agent X 循环。
